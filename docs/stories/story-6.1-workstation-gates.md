# Story 6.1: Workstation gates for the workshop and the research notes they feed

**Status:** Approved

## Story

As the author about to let work orders run in containers that hold a model token,
I want the gates of PRD section 8 run on my workstation, by AD-126's procedures, each recorded as an E-entry that says what was seen, who ran it and what it changes,
so that the account, the network, the engine and the binary are known to allow the workshop before any Slice A code is written, and a failed gate reshapes its FR first (FR-0).

## Acceptance Criteria

1. **E26, gate 7: terms and account** (AD-126 row 7, FR-5, FR-1; owner; first). The owner records which Claude account the work floor uses (personal or an employer plan, named by kind only); whether a `setup-token` token driving unattended workers on that machine is ordinary use under that plan (S3) and, for an employer plan, the employer's position; whether an API key is available; whether Docker Desktop's subscription terms hold where it runs. Pass: a token accepted, or an API key available. The entry states which `auth` each floor will set (D-203); with neither, it says v0.6 stops at Slice 0 (P-52). Proof: research notes entry E26.
2. **E27, gate 0: the work network** (AD-126 row 0, FR-4, FR-1; owner, agent-prepared). Addendum section 1 item 4 (verified on this workstation's network: direct, public chain) is copied in as the container half; the owner states whether this is the work floor's network. If it is not, on the work floor's machine and network: proxy variable names in a host `claude` session's environment (names only), Windows proxy settings (`ProxyEnable`, presence of `ProxyServer` and `AutoConfigURL`), the issuer of `api.anthropic.com` seen from the host, and, as uid 1000 on the default network, `curl -v https://api.anthropic.com` with its issuer and outcome; with a PAC file, the proxy it names for that host. Pass: direct with the public chain, or an unauthenticated proxy (`upstream_proxy`) and, for a non-public issuer, `ca_file`. Proof: research notes entry E27, stating the floor's `upstream_proxy` and `ca_file` (or none) with placeholder hosts.
3. **E28, gate 9, first half: the musl build** (AD-126 row 9, AD-100, D-202; agent). `rustup target add x86_64-unknown-linux-musl` on the workstation (the repository's `rust-toolchain.toml` changes in story 6.5, not here); `cargo build --release -p officina-core --target x86_64-unknown-linux-musl` with `rust-lld` as linker given on the command line, recording the linker flavour flag that works; a scratch std-only program outside the repository that resolves a name and opens a tunnel through a CONNECT proxy, built the same way, copied into a `FROM scratch` probe image and run as uid 65534 on a probe internal network plus a probe bridge, resolving names through the engine's mounted resolver file. Pass: both build and the program reaches an allowed host through the stub proxy. On failure, AD-100's fallback is listed for the owner's approval before story 6.5 (D-203). Proof: research notes entry E28 (first half); the second half closes story 6.8.
4. **E29, gate 1, first half: images, options, mounts, copies** (AD-126 row 1, PRD question 1 as amended, AD-99, AD-102, D-202; agent, then owner for the mount). In a scratch folder, a probe Dockerfile drafted to AD-99 (Debian slim by digest, the listed packages sorted with `--no-install-recommends`, uv by checksum, the documented Claude Code installer at the host's version in a build stage, user `worker` uid 1000, setuid and setgid bits removed, an empty `ca/` folder); built with the build's HTTPS traffic through the stub proxy so the installer's hosts are logged; record those hosts, whether the installer checks the binary's checksum, the image size. A probe project image `FROM` it with the default builder and no pull. Then AD-102's `Worker` options by hand (`--user 1000:1000 --read-only --cap-drop ALL --security-opt no-new-privileges:true --init --pids-limit`, memory equal to swap, `--log-driver local` with AD-98's options, a named volume at `/work`, a tmpfs `/tmp`) with a probe command: `docker cp` of a folder into the created container's volume, then out of the stopped container, with owners and modes recorded; the container keeps running after the console that started it closes. Also recorded (D-203; review F16, F40, F41): one real `docker cp <container>:/work/.officina/out -` stream from a probe container whose `out` folder holds a file with a name over 100 bytes and one with an accented name, saved as a byte fixture for story 6.13's `tar` section (whether it carries PAX records is what it shows); whether `docker create` starts a CLI plugin (Docker Desktop's CLI hooks), by watching child processes of `docker.exe`; the current builder and its driver (`docker buildx ls`). Owner: the same options with a git-ignored folder of one of his projects inside the synced tree mounted read-only; read a file; a rewrite and a create both fail with "Read-only file system"; then, in a scratch folder he makes inside that mount, a directory junction pointing at another scratch folder outside it, and whether the container sees the junction's target (D-236, review F11). Record Docker Desktop, engine, kernel and WSL versions. Pass: all of these. On failure D-203 applies (writable mount stops Slice A; copy fallback; `--build-context`; release-manifest path; junctions followed make doctor count reparse points). Proof: research notes entry E29 (first half) and the fixture file handed to story 6.13; the second half closes story 6.8.
5. **E30, gate 2, first half: no route out** (AD-126 row 2, AD-104, D-202; agent). On AD-104's layout (a probe `--internal` network, a probe bridge, the stub proxy attached to both, a probe worker on the internal network only, `HTTPS_PROXY` naming the stub), by hand: TCP to public addresses, an IPv6 socket, UDP DNS to a public resolver, resolution of an outside name, ICMP; `host.docker.internal`, `gateway.docker.internal` and `http.docker.internal`; the engine host's address on ports 22, 80, 2375 and 2376; the stub's ports other than its listener; a second probe run's network. Pass: every attempt fails, and an allowed host is reached through `HTTPS_PROXY`. Outside names resolving selects the `--dns 0.0.0.0` branch (D-203). Proof: research notes entry E30 (first half); the second half closes story 6.10.
6. **E31, gate 3: a worker authenticates with a setup token** (AD-126 row 3, framing step 0 item 7, D-202; owner). The owner runs `claude setup-token` in a terminal with a browser and stores the token with `cmdkey /generic:officina:workshop /user:workshop /pass` (D-38). In the gate 1 probe base, as uid 1000, a fresh `CLAUDE_CONFIG_DIR` on the volume, `--env CLAUDE_CODE_OAUTH_TOKEN` with the value set in his own console only, FR-7's argument vector with the prompt on stdin, on a probe internal network behind the stub proxy whose allow-list is `api.anthropic.com` alone; a scratch repository cloned into the volume with a git-ignored `.claude` holding no hook; a prompt that edits a file, runs `git status` and commits. Record: no dialog or login prompt, exit 0, the commit (`git log` before `docker rm`), every host the stub allowed and refused, and that `claude --help` at the image's version lists `--permission-prompts`. The owner also saves the run's `docker logs --timestamps` output; the agent replaces every value (texts, ids, paths) by placeholders, keeping the line shapes, as the fake engine's `logs` fixture (review F49). A run failing for want of a host adds the hosts recorded (first `platform.claude.com`) and runs again. Pass: all of these. Proof: research notes entry E31, its own entry, and the fixture file; the window half closes story 6.19 (D-202, review F5).
7. **E32, gate 4, first half: hooks from a read-only mount** (AD-126 row 4, PRD question 4 as amended, D-202; owner). A scratch repository whose git-ignored `.claude/settings.json` declares, for `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop` and `SessionEnd`, a hook appending one line to `$HOME/hooks-gate.log`; the folder mounted read-only at its place in the clone; a worker run by hand as in AC 6 with `--include-hook-events`; the owner copies the log out with `docker cp` before `docker rm` (nothing collects a by-hand run) and saves the stream from `docker logs`; the agent compares them. In one real host session at work, the owner records the kinds of source each instruction file and hook comes from (`/memory`, `/hooks`), placeholder paths only. Pass: every configured event's hook ran and the stream reports the events it can. Proof: research notes entry E32 (first half); the second half, one window run per owner project that declares hooks, closes story 6.20.
8. **E33, gate 5: stream fields** (AD-126 row 5, FR-8; owner, agent compares). On AC 6's saved stream, plus a by-hand run whose `PreToolUse` hook names a missing program: the presence and names of `system/init` model, tools and MCP servers; `result` subtype, error flag, cost, turns, duration and session id; `system/api_retry` `error`; hook lifecycle events with their exit code. Pass: all present. Without exit codes, `hook_failed` is not built (D-203). Proof: research notes entry E33; story 6.12 derives `STREAM_FIELDS` from it.
9. **E34, gate 6: the budget cap** (AD-126 row 6, FR-7; owner). AC 6's setup with `--max-budget-usd 0.01` on a multi-step prompt; record the result subtype and the reported spend. Pass: the run stops on the budget; otherwise `max_usd` is dropped (D-203). Proof: research notes entry E34.
10. **E35, gate 8, first half: the browser base** (AD-126 row 8, FR-16, D-202; owner; before story 6.22). A probe browser Dockerfile in a scratch folder `FROM` the probe base (Chromium and its libraries from Debian, setuid and setgid bits removed again); a probe project image adding the owner's Svelte project's Playwright and browser build; its end-to-end suite run by hand on a probe internal network behind the stub proxy, against the project's own server inside the container; a page on an off-list host fails with a refusal in the stub's log; the Chromium flags the suite needed recorded. Proof: research notes entry E35 (first half); the second half closes story 6.22.
11. **E36, question 10: revocation** (AD-126 row 10; owner). Where a `setup-token` token is revoked, from the account settings. Proof: research notes entry E36; story 6.24's README sentence follows it (D-203).
12. **Nothing left behind** (AD-126 preamble, D-201). Every probe container, network, volume and image carries `officina-probe=1` and is removed; `docker ps -a`, `docker network ls`, `docker volume ls` and `docker image ls` filtered on that label are empty at the end and before and after each gate; scratch folders lie outside the repository; no token reaches a file, a log or a research note; the repository's working tree changes only in `docs/research-notes.md`. Proof: each entry's before and after listings; `git status` at the end.
13. **Recording rules** (D-201). E37 and E38 are reserved now for stories 6.20 and 6.24, so the next epic starts at E39 (review F29). Proof: review of `docs/research-notes.md`.
