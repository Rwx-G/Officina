# Story 6.8: Workshop images, Build images and the Linux programs

**Status:** Review

## Story

As the author who approves what a worker's tools are,
I want the base, gateway and project images built on my click from Dockerfiles Officina holds or I approved, each labelled with what built it and measured for the programs that matter, and a launch to refuse any image whose labels or measurements do not match,
so that a worker never runs on an image I did not approve, a project image can neither replace Officina's programs nor add a credential name, and a change of Officina, of a Dockerfile or of the CA file is seen before a run.

- Waits for: the gate 9 and 1 entries; stories 6.3, 6.4, 6.5, 6.7 and 6.25 merged (the build's proxy, D-621).
- Why the CA comes first and why the proxy is a build argument (D-611, D-612): on an inspecting network every HTTPS step of a build fails until the root is in the store, and a container started by `docker build` gets no proxy unless one is passed (addendum section 1 item 2); Docker keeps its predefined proxy arguments out of the image history, so the work network's proxy never becomes a label or a layer.
- Builds pass `--network default` and the `docker`-driver builder because the engine's or the author's builder defaults may change (R61), and a `docker-container` builder cannot see local images, which `--build-context` does not fix (review F41). A project Dockerfile's steps fetch what they fetch at the author's risk (FR-1). Images are never pulled ready-made; the Debian base is pulled by digest.
- Why measure (review F4 b): `officina.entry.sha256` on a project image is a label Officina sets at build, not a measurement; an approved project Dockerfile, possibly changed by an imported branch where `Dockerfile*` is only a sensitive group, could `COPY` over `officina-entry` or `claude`, and the battery, the packer and the inventory would then run the project's programs. The battery's validity keys on the measured digest too (story 6.10).
- Why reserved names (review F13): the image's `ENV` applies under the vector's names, so an `ENV ANTHROPIC_API_KEY` or `ANTHROPIC_BASE_URL` would break "exactly one of the two names" (FR-5) or redirect the API, and the battery's expected set includes the image's names, so it could not see it.
- `officina.claude.version` is not compared at launch: Claude Code updates itself on the host (E11), and comparing it would force a rebuild and a battery each time (AD-99); doctor warns instead.
- No employer content: the probe project image in AC 7 uses a scratch Dockerfile; the owner's folder is "an owner project".
