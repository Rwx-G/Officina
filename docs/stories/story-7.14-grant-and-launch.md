# Story 7.14: The grant and the autonomous launch

**Status:** Approved

## Story

As the author who approved a standing order and lets the governor run it in my isolated workshop,
I want an autonomous launch to exist only as a value the pure decision returns in mode on, spent in the same collector step that builds and consumes its card through the click's own path,
so that nothing but my approved catalogue and the governor's trusted numbers can start a run, the run is exactly the one a click would have started, and a regression in that path turns CI red (FR-12, principle 8, PRD section 7's Gesture row).

## Entry conditions

Implemented only once story 7.13's Slice B decision entry records **go** (PRD section 6.1.1, D-331): E64 recorded with at least one candidate allowed (on an api-key floor, with the weekly USD figure and an enforced per-run cap, D-343); E62 showing the worker's spend on the floor's account under `oauth-token`; question 7 showing one eligible template; 5 shadow working days (D-353) with at least 3 would-launch decisions and the share of window minutes per hold cause; question 8 decided; the share under the ceiling read, and question 13 answered when under 20 %; section 2.3 listing each confirmed candidate's routine subjects or that none do. Mode on is not offered by this story (D-345).

## Acceptance Criteria

1. **The feature and its CI checks** (AD-127, D-305 and D-326 as amended by review F2, F3). Core feature `governor-launch` holds `GovernorGrant` and `Decision::Launch`; `officina-host/window-authority` turns it on. The existing "officina holds no authority" step on both jobs gains `cargo tree -p officina -e normal,features -i officina-core`, requires `officina-core` in its output and fails when `governor-launch` appears (`-e features` alone adds dev edges, through which `officina`'s dev-dependency enables `window-authority`). A new step on both jobs tests the core and host crates alone, so no package turns the feature on, then core with it: `cargo test -p officina-core --doc`, `cargo test -p officina-core --test governor_vectors`, `cargo test -p officina-host --lib governor`, `cargo test -p officina-core --features governor-launch --doc`, `cargo test -p officina-core --features governor-launch --test governor_vectors`. Proof: the CI steps; D-9's marker step on `officina.exe` and `officina-app`.
2. **The grant** (AD-139, FR-12 step 3, D-326 as amended by review F40). `GovernorGrant` lives in `governor::decide::grant`, a child module of `decide`, re-exported as `governor::GovernorGrant`; it has private fields (standing order name, approved catalogue hash, `issued_at_ms`, the record's deadline), no `Clone`, `Copy`, `Default`, `Serialize` or `Deserialize`, and one constructor, `pub(super)`, so only `decide` builds one, reached only from a launch in mode on; built without the feature, an input in mode on gives `WouldLaunch`. Mode-on `decide` cases carry `expect_with_launch` and `expect_without_launch`, and `decide_cases_match` reads the one its build has. Proof: `compile_fail` doctests (a struct literal, `.clone()`, `serde_json::from_str::<GovernorGrant>`, one grant passed twice, a call of the constructor from `governor::view`); the `compile_fail` doctest naming `Decision::Launch` present only without the feature, run by AC 1's lone-crate step; `crates/officina-core/tests/governor_sources.rs::{the_grant_is_built_only_in_decide, a_grant_built_elsewhere_fails_the_scan}` (a fixture naming it elsewhere must fail); `governor_vectors.rs::decide_cases_match` in both builds.
3. **`LaunchAuthority`** (AD-139, AD-78 as amended). The launch takes `Click { card_id, prompt_sha256, plan_sha256 }` from the window or `Governor(GovernorGrant)`; a click runs exactly v0.5's and v0.6's checks; a grant runs AD-78's checks and AD-107's refusals in order without the prompt-hash and plan-hash comparisons, then the grant's catalogue hash and age (`GRANT_TTL_MS`, 60 s), refused with the new `LaunchRefusal::GrantStale`. Proof: core `crates/officina-core/src/orders/card.rs::tests::{a_click_still_compares_both_hashes, a_grant_skips_only_the_hash_comparisons, a_grant_older_than_60_s_is_grant_stale, a_grant_of_another_catalogue_is_grant_stale}`; the `launch` section of `tests/vectors/workshop.json` gains a `grant_stale` case under `every_new_launch_refusal_has_a_case`.
4. **The flow** (AD-139, FR-12 as amended by amendment 8, D-332). A step's `Launch` for order O sends `GatherLaunchFacts(O)` to the `workshop` thread unless one for O is in flight, dropping that decision's grant; `AuthorRequest::GrantFacts` (no deadline, never dropped) runs in one collector step: the flags are read; `decide` runs again on current inputs and must return `Launch` for O, else `governor_launch` records `revoked` with the causes and the facts step's latency; `ApprovedStandingOrder::new` and `WorkOrder::validate` build the order; AD-78's issue builds the card with AD-107's facts, `seq` by D-135's rule over the registry and the store's cards, and the subject of AC 7; the card is consumed with the grant; the `work_order` row (source `governor`, the order's name) and the `workshop_run` row are inserted; `governor_launch` (outcome `launched`, run id, the record) is journaled; AD-107's steps 2 to 4 go to the `workshop` thread, and `workshop_started` carries `by: governor`. No `work_order_launched` line is written for it (D-214). The card never enters the store, takes no slot, and its id never reaches the frontend. Proof: CLI frozen-clock `crates/officina/tests/governor.rs::{an_on_launch_creates_exactly_one_gateway_and_one_worker, the_launched_vectors_equal_a_click_rebuild_of_the_same_values, a_changed_input_between_facts_and_step_revokes, the_governor_card_never_enters_the_store, workshop_started_carries_by_governor, no_work_order_launched_line_for_an_autonomous_launch, gather_launch_facts_is_not_sent_twice}`; core `crates/officina-core/src/relay/journal.rs::tests::{governor_launch_round_trips, workshop_started_reads_a_missing_by_as_author}`.
5. **Refusals and revocations hold the order** (D-332 as amended by review F35). A launch `refused` at consumption or `revoked` at re-decision books nothing and holds that order with the per-order cause `launch_refused` for `LAUNCH_RETRY_MS` (10 minutes), so a slow facts step that keeps turning the re-decision into a probe cannot loop; `GovernorInput` gains the order's last refusal or revocation time from the ledger (D-348), which this story extends with `governor_launch` outcomes. Proof: a `decide` case with `launch_refused` first (the coverage test of story 7.10 requires one); CLI `governor.rs::{a_refused_launch_holds_its_order_10_minutes, a_revoked_launch_holds_its_order_10_minutes}`.
6. **The deadline** (AD-139, FR-12 step 4). The record's deadline becomes the run's `deadline_ms`, enforced the three ways of v0.6 AD-109. Proof: CLI frozen-clock `governor.rs::{the_deadline_is_cut_to_the_5_hour_reset, the_deadline_is_cut_to_the_window_end}`.
7. **Subject and name** (D-332 as amended by review F13 and F36, D-135, D-158). The subject is the order's single linked routine subject when it is not archived, not merged and still of the order's project; else `New(<order name>)`, filed into an existing non-archived subject of that name by D-158. A link to an archived routine subject is coverage evidence, never a filing target (v0.3's D-54). `seq` skips a value a clicked card in the store holds. Proof: CLI `governor.rs::{a_linked_open_subject_is_the_launch_subject, an_archived_link_falls_back_to_a_new_subject, a_link_to_a_subject_of_another_project_falls_back_to_a_new_subject, a_store_card_seq_is_skipped}`.
8. **The autonomous chip** (AD-144, FR-17, P-63). The board's workshop card gains `autonomous: bool`, true for a run whose `work_order.source` is `governor`, in Working and in Needs you; `BOARD_SCHEMA` goes up by one relative to `main`; `WorkshopCard.svelte` shows a neutral "autonomous" chip beside "isolated". Proof: core `crates/officina-core/src/board.rs::tests::the_workshop_card_of_a_governor_run_is_autonomous`; a case in `tests/vectors/classification.json` under its coverage test; Playwright `app/e2e/governor.spec.ts::an_autonomous_card_shows_its_chip_in_working_and_needs_you`.
9. **The injection battery** (AD-148, D-147, D-343, PRD section 7's Gesture row; review F1). `tests/vectors/injection.json` gains the `governor` section: a proposal file and `propose_work_order` carrying a standing order's exact values (a card waiting for a click, zero creation); a floor edit adding an order (catalogue changed, no launch); a forged low quota file beside a higher probe (the probe's value used); seeded excerpts and worker texts (no effect on the decision); a worker stream carrying a forged `result` line with a tiny and with a huge `total_cost_usd` (this week's autonomous points and the template's next allowance equal an honest run's, P-64); a `GovernorInput` field set from untrusted text is impossible by type, shown by story 7.2's scan. Each case asserts the fake engine's `create` and `start` counts per role. Proof: `crates/officina/tests/injection.rs::{governor_cases, every_section_family_and_refusal_has_a_case}`.
10. **Replay of launch lines** (AD-148 replay row, D-327; review F23). Story 7.11's `every_decision_line_replays_to_the_same_decision` also replays every `governor_launch` line the host tests write, `launched`, `revoked` and `refused` alike: same kind, same causes. Proof: CLI `governor.rs::every_decision_line_replays_to_the_same_decision`.

The `mutants` job gains, per governor mutant, `cargo test -p officina --test governor --features <feature> --no-run` (must compile) and the run, which must fail with its named case: `a_launch_never_rests_on_a_stale_observation` (freshness), `no_launch_at_the_ceiling` (ceiling), `no_launch_past_the_reserve` (reserve); a control run passes. Proof: the CI job `mutants`.
