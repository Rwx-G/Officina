# Epic 5 decisions

What the PRD, the addendum and the code leave open or state twice for v0.5, settled while writing the Epic 5 stories on 2026-10-28 under the owner's delegation of design decisions, then reworked the same day after a review of the stories: every finding accepted, the existing decisions amended in place with the finding they answer (`review Fn`), and new rules added from D-151. Numbering continues Epic 4's (`epic-4-decisions.md`; D-180 to D-189 are Epic 4's rework), so a `P-n` or `D-n` is unique across epics and Epic 5 stories cite all four files. Stories cite these decisions and name the test that proves each one; this file states the rule, never the test data. A later change edits this file with the fact that motivates it, like the architecture.

The stories were reworked again on 2026-10-28 against PRD section 9, the addendum's section 6 and v0.2 to v0.4 as they stand on `main`: section "Rework against the addendum and v0.4 as built" (D-560 onward) wins over every earlier section where they differ.

"The addendum" is `docs/architecture-v0.5.md`. A gate's E-number is the research notes entry story 5.1 (or, for E25, story 5.13) writes for it (D-125).

## Spawn and untrusted text

- **D-128.** (Amended by D-561: the contained kinds take v0.3's allow list instead of the removals below; and by D-562: no kind runs a shim, and the lint's sites are those of the code as built.) The spawn module:
  - `ClaudeVector` has private fields and getters; the per-kind builders of `officina-core::spawn` are its only constructors (a `compile_fail` doctest on a struct literal), so a `WorkOrder` vector can only come from `spawn::work_order(&WorkOrder, seq)`. `BackgroundId::parse` wraps `focus::is_valid_attach_id`, the one copy of the rule (review F47).
  - **Environment** (amended, review F1, F4, F13). Every kind removes `SESSION_ENV_REMOVED`. Only the contained kinds (`TriageCall`, `ReviewCall`, `Orchestrator`) also remove every `OFFICINA_*` name; the session kinds (`Agents`, `Version`, `Attach`, `Logs`, `WorkOrder`, `Answer`) inherit the base environment's `OFFICINA_*` names unchanged, as a session the author starts would, so its hooks find the author's home, floor and `OFFICINA_NO_EXCERPTS`. Every kind removes `CLAUDE_CODE_DISABLE_AGENT_VIEW` except `Orchestrator`, which sets it to `1`. Each kind's rule is one exhaustive `match` in core. On Windows names compare ignoring ASCII case. Since the orchestrator drops the prefix, its MCP config's `env` gives `officina mcp` `OFFICINA_HOME`, `OFFICINA_NO_EXCERPTS` (the window's effective value) and `OFFICINA_CLAUDE_BIN` (the resolved path) explicitly. `spawn::execute` applies the rule to a base environment it receives as an argument (D-86), so no test sets a process variable.
  - Kinds join `VectorKind` with the story that builds them, each with its golden case, so the coverage test over `VectorKind::ALL` holds at every merge: `Agents`, `Version`, `Attach`, `TriageCall` (5.2), `WorkOrder` (5.5), `Logs` (5.10), `Answer` (5.11), `ReviewCall` (5.13), `Orchestrator` (5.16). `VectorKind::is_launch()` is an exhaustive `match` (review F5).
  - **Authority** (amended, review F5). The launch half compiles under `window-authority`, with its own error type carrying `AUTHORITY_MARKER` (D-9); `execute` built without the feature refuses a launch kind, before any process starts, with an error that carries no marker. A host unit test compiled only without the feature iterates `VectorKind::ALL` and asserts that refusal for every launch kind, and a CI step on both jobs runs `cargo test -p officina-host --lib spawn` alone, so no other package turns the feature on.
  - **Jobs and pipes per kind** (review F10): `Agents`, `Version` and `Logs` keep today's job, terminated with its tree on timeout; `TriageCall` and `ReviewCall` run in a kill-on-close job; `WorkOrder` runs in no job, and its deadline kills the direct child only, since `claude --bg` may start the supervisor of every background session; console kinds run in no job. A `WorkOrder` whose `claude` exits 0 while a process it started still holds the output pipes is `started` with what was read.
  - **Shims** (review F28). On Windows `Agents` and `Version` accept `.exe`, and a `.cmd` or `.bat` through `cmd.exe /d /c`; every other kind accepts only `.exe`, whatever `OFFICINA_CLAUDE_BIN` names.
  - `src/` of `officina-host` holds exactly three `#[expect(clippy::disallowed_methods, reason = ...)]` sites (`spawn`, `relay::run`, `git`), checked by a test that reads the crate's sources; story 2.10's WSL probe moves into `relay::run` (review F18); tests and examples carry their own `expect`.
  - Every `git` call of `host::git`, the tree fingerprint's included, sets `GIT_OPTIONAL_LOCKS=0` with D-22's flags: a read never writes the index (R42; D-154 adds the meeting's hardening).

  (5.2, 5.5, 5.7, 5.10, 5.11, 5.13, 5.16)
- **D-129.** (Amended by D-582: the review modes are a `review-*` family beside the fake's `triage-*` modes.) Every call of `officina-fake-claude` appends one line of JSON, `{"argv": [...], "cwd": "...", "env_names": [...]}`, the names sorted and never a value, so tests compare argument vectors element by element and assert removals and settings by name; a test parses the format (review F12).   - `logs` (5.10): prints a fixture holding CSI, OSC and other ESC sequences and an error line built from an entry of `LOG_ERROR_MARKERS`, never a typed string (review F42);
  - `resume` (5.11): marks the entry whose `sessionId` follows `--resume` `busy` in the fixture;
  - `review` (5.13): answers the decision named by a `FAKE-REVIEW:` token in stdin.

  Configuration stays the sidecar or `FAKE_CLAUDE_*` (D-86). (5.2, 5.5, 5.7, 5.10, 5.11, 5.13)
- **D-130.** `Untrusted<T>` wraps payload fields (types serialized to the window, the CLI or an MCP client) and registry read-backs whose text came from a session or a model, including `Card.last_message_tail` (D-182), the relay view's `gate_denied.command_excerpt`, session-supplied `params` and `refused.detail`, and every proposal text and invalid reason (review F8). ## Work orders

- **D-135.** Cards live in the collector's memory (AD-78), at most 32, the oldest evicted first; the card id is drawn by the host and passed to core.
  - **The name** (amended, review F2). The store reserves `seq` when it issues a card: one more than the larger of the registry's highest `seq` for the template and the highest `seq` any card of that template holds in the store; an edit keeps it. The card's vector is built with it, `insert_work_order` stores it, and what runs is byte for byte the card's argument vector. A launch whose name the registry already holds is refused `name_taken` (`LaunchRefusal`).
  - `launch_work_order(card_id, prompt_sha256)` sends `AuthorRequest::LaunchCard`: the collector runs AD-78's checks in order, consumes the card, inserts the `work_order` row with outcome `launching` and answers with the vector; the command runs `spawn::execute` on its blocking thread and sends `AuthorRequest::LaunchOutcome`, which records the outcome and journals `work_order_launched` once. A consumed card never launches again: a failed spawn burns it, and the author issues a new card (FR-4, D-29's rule).
  - **Deadlines** (amended, review F14). D-92's deadline applies to `LaunchCard`; `LaunchOutcome`, like 5.11's confirmation lines, carries none and is never dropped, so a late outcome is still recorded.

  (5.7)
- **D-136.** A `work_order` row's id is the id of the card it consumed. The history's `unbound` (a `started` order not bound 10 minutes after launch) and "printed id differs" (`printed` does not contain `bg_id`) are computed by the view builder from stored columns, never stored. `launching` rows older than 2 minutes become `unknown` in the start sequence, before the first view (AD-81), and on the collector's own tick (review F14).
