# Story 8.3: Effect, target, scope, relay action and bound path keys, and the canonical format

**Status:** Approved

## Story

As the author who declares what each action does and where sessions and workers may act,
I want `effect`, `target`, `targets`, `[project.scope]`, `relay_actions` and, when gate 1 calls for it, `bind` validated in core and made part of the catalogue I approve, a forgotten `effect` read as a write and reported without dropping the action,
so that every later scope decision rests on keys I approved, and an edit to any of them voids my approval before it changes what runs.

## Acceptance Criteria

1. **Entry condition** (P-72, D-405, D-1301, D-1310; review F38). The v0.8 gate 0 and gate 1 entries are recorded; a slice is confirmed (8.2 has recorded Slice A's trigger, or the gate 2 and 3 first halves have passed) or the gate 1 entry has called for 8.8; story 2.13 is on `main` (it is). No v0.7 story is a condition, in either order (D-1301). Otherwise this story waits, so the format is never bumped for nothing. Proof: the gate entries, 8.2's entry and `epic-8-decisions.md`.
2. **Raw keys** (AD-151, AD-152, AD-155, AD-156, AD-23, D-434; review F25). The action table gains `effect`, `target` and `targets`. `ProjectEntry` is parsed with `deny_unknown_fields`, so `[[project]]` gains `scope` and, per the gate 1 entry (D-403), `bind` as raw `Option<toml::Spanned<toml::Value>>` fields converted in phase 2, as `[[action]]` is; `relay_actions` sits in v0.6's raw `[template.workshop]` table and is converted in phase 2 too. `RELAY_KEYS` gains `project.scope` and `project.bind`, so a schema 1 floor naming them is refused as today, and a malformed scope or bind never invalidates the floor the board uses; the hook's gate reads phase 1 only. Proof: core `crates/officina-core/src/floor.rs::tests::{a_malformed_scope_table_keeps_the_board_floor, a_malformed_bind_keeps_the_board_floor, scope_and_bind_are_relay_keys}`; the existing D-7 test over `RELAY_KEYS` stays green.
3. **Effect and target** (AD-151, FR-1 as amended by amendments 1 and 3, D-406). `catalogue::Effect` (`read`, `write`) is a `closed_enum!`. Phase 2: `effect` absent reads `write` on a program action and `read` on an HTTP action. Story 2.13's notice type, `catalogue::NoticeKind` as built (`RemoteCommandValue`, `TemplatedValue`, carried by `RelayView.notices`, D-1306), gains the kinds `effect_undeclared` (a program action without `effect`), `target_undeclared` (a write without `target`) and `target_not_limit` (computed on `ArgTemplate`: when the last segment of `program`, split on `/` and `\` and lowercased, is `ansible-playbook`, the target's placeholder is not the whole item after a literal `--limit` or `-l`, nor the item `--limit={target}`); they keep the action and sit outside the canonical form, like 2.13's own kinds. Issues (`IssueKind` variants, each with a failing fixture, D-132): `target` or `targets` on a read; `target` naming none of the action's parameters; `targets` naming no valid read action, one whose parameter names are not a subset of the write's with the target among them, or one whose class is not `free` (it runs inside the resolution with no check of its own, D-434, review F27); `effect = "write"` on an HTTP action. Officina infers no effect. Proof: core `crates/officina-core/src/relay/catalogue.rs::tests::{every_issue_kind_has_a_case, a_missing_effect_reads_write_on_a_program_action, a_missing_effect_reads_read_on_an_http_action, target_not_limit_accepts_limit_l_and_limit_equals, target_not_limit_ignores_other_programs, targets_params_must_be_a_subset_with_the_target, a_targets_action_must_be_free}` (the first iterates `IssueKind::ALL`).
4. **Notices and issues** (D-406, review F1, F26). Each v0.8 notice kind's fixture leaves a valid action, and each action-table issue kind's fixture drops it, as today; a floor whose only findings are notices approves and runs as a clean one. `IssueKind::keeps_action` and an issue level are not built. Non-action issues have their stated effects (D-434): an invalid scope table gives an empty scope (AC 5), an invalid `bind` an empty `bind` and a doctor warning (AC 8), an invalid `relay_actions` entry is removed from the list (AC 6). Proof: core `catalogue.rs::tests::{each_notice_kind_fixture_leaves_a_valid_action, each_action_issue_fixture_drops_its_action}` (the first iterates the notice kinds' `ALL`); CLI `crates/officina/tests/run.rs::an_action_with_only_notices_runs`.
5. **The scope table** (AD-152, FR-2). `[project.scope]`: `targets` and `hosts` (the latter only when the gate 1 entry recorded a parsed listing, D-403), each `values` or `pattern` with `CanonicalParam`'s type under AD-30's value rules and AD-23's pattern limits; `on_order`, a map from a parameter name to values. Issues: an unknown key; a rule with neither or both forms; an `on_order` name that is a parameter of no action the project lists; a value failing AD-30. An invalid scope table gives its issue and an **empty** scope, never a partial one. Proof: core `crates/officina-core/src/relay/scope.rs::tests::{an_invalid_table_gives_an_empty_scope, values_and_pattern_are_exclusive, on_order_names_a_listed_parameter}`; one fixture per new kind through `every_issue_kind_has_a_case`.
6. **Relay actions** (AD-156, FR-5 as amended by amendment 6, D-407, D-426, D-427). `relay_actions`: at most 16, distinct; an invalid entry is removed with its issue: an action unknown or dropped; one that some project of the template does not list; one whose effect is not declared `read` (a program action needs `effect = "read"` written; an HTTP action reads `read` when `effect` is absent); a class other than `free` or `after-check`; an action carrying a story 2.13 notice (`RemoteCommandValue`, `TemplatedValue`), since a worker never feeds a value into a remote shell or a template (review F1). An `ansible-playbook` read that no write names as its check, listed here, gets the notice kind `unscoped_check_mode_read` ("a check-mode read judged on its parameter rules only", D-427, review F2). Proof: core `crates/officina-core/src/workshop/floor.rs::tests::{relay_actions_are_reads_listed_by_every_project, an_undeclared_program_effect_is_refused_in_relay_actions, an_http_read_without_effect_may_be_listed, a_human_or_auto_action_is_refused_in_relay_actions, an_action_with_a_program_value_notice_is_refused_in_relay_actions, an_invalid_entry_is_removed_and_the_rest_kept, an_unscoped_check_mode_read_carries_its_notice}` (the fifth iterates story 2.13's two value notice kinds); fixtures through `every_issue_kind_has_a_case`.
7. **Canonical form and format** (AD-151, AD-152, AD-156, AD-24, AD-76, D-131, D-405, D-434). `CanonicalAction` gains `effect` (explicit, deserialised with a named default of `write`, never a derived `Default`, review F24), `target` and `targets` (optional); `CanonicalProject.scope: CanonicalScope` (explicit and empty when the table is absent; `on_order` a sorted map of sorted values) and `bind` sorted; `CanonicalWorkshopTemplate.relay_actions` sorted. Notices stay outside it (story 2.13). `CANONICAL_FORMAT` goes up by one relative to `main` at this merge (5 at this rework; whatever v0.7's 7.2 left if it merged first, D-1301), and AD-24's golden hashes are re-pinned once, the relay-section hash of story 6.2 (D-244) included. Proof: core `crates/officina-core/tests/catalogue_hash.rs::{golden_fixture_hash_is_pinned, relay_section_hash_is_pinned, a_previous_format_approval_is_void, every_canonical_field_changes_the_hash, a_previous_format_snapshot_reads_effect_write}` (as built, D-1306; the third loads `tests/data/relay/approved-previous-format.json`, refreshed from the real previous form, and asserts AD-76's four facts; the fourth covers every new canonical field by construction); `catalogue.rs::tests::{writing_effect_write_where_absent_keeps_the_hash, an_empty_scope_table_and_no_table_hash_alike, relay_action_order_does_not_change_the_hash, a_changed_scope_value_changes_the_hash, v08_notices_do_not_change_the_hash}`.
8. **Bound paths, only when the gate 1 entry recorded ignored roles or collections** (AD-155, FR-4, D-403, D-434). `[[project]] bind`: at most `BIND_MAX_PATHS` (8), relative to the project folder, `/` separators, no `.` or `..` segment, not `.git` or under it, no duplicate; an invalid `bind` gives its issue, an empty `bind` and a doctor warning. Otherwise this AC is not built and `bind` is an unknown key. Proof: core `catalogue.rs::tests::{bind_paths_follow_their_rules, an_invalid_bind_is_empty, bind_order_does_not_change_the_hash}`; host `crates/officina-host/src/relay/doctor.rs::tests::an_invalid_bind_warns`; fixtures through `every_issue_kind_has_a_case`.
9. **Diff** (AD-24, AD-35). `catalogue::diff` gains `effect`, `target`, `targets`, `bind` per action or project, a scope section per project (values added and removed, patterns changed, `on_order` entries) and `relay_actions` per template; the banner shows them with the existing rules. Labels are 8.4's. Proof: core `catalogue.rs::tests::{diff_lists_scope_changes, diff_lists_effect_and_relay_action_changes}`.
10. **Validated, not enforced** (D-405, P-53's pattern). Until Slice A (8.6) or Slice B (8.10) uses them, the keys change no run: a write outside its declared scope runs under its class, and no worker exists to read `relay_actions`. Proof: CLI `run.rs::a_declared_scope_changes_nothing_before_its_slice`.
11. **Documentation** (D-423). `CHANGELOG.md` `[Unreleased]` under Added: the keys; under Changed: the catalogue format goes up, voiding the approval once (R39's upgrade note). README "Relay scope and workers (v0.8, in progress)": the keys with a placeholder example; beside `effect`, that an Ansible `--check` action is a read only if no task it can reach sets `check_mode: false` or delegates, with gate 1's counts; scope as action pairs until Slice A exists (PRD section 4.1); beside `relay_actions`, the exposure note and that an action whose values a program reads (story 2.13's notices) cannot be listed. Story 2.13 owns the correction of the README's "no shell ever reads it". Proof: review; `crates/officina/tests/readme.rs` stays green.
