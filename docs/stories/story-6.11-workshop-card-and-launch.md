# Story 6.11: Workshop cards, launch checks, the credential and the launch flow

**Status:** Approved

## Story

As the author who launches a workshop run with the same one click as any work order,
I want the card to show the base and its tip, what will not be carried, the hosts, mounts, image, deadline and budget, and the launch to recheck everything on that card's id, prompt hash and plan hash before the engine creates anything,
so that one pointer click on what I saw is the only way a container starts, and the credential reaches only the worker's `create`.

## Acceptance Criteria

1. **Card facts** (AD-107, FR-6, D-239). For a template with `[template.workshop]`, v0.5's `issue_card` (AD-78) adds `WorkshopCardFacts` (ts-rs): base choices (the template's `base` list, each with its tip from `rev-parse --verify refs/heads/<branch>^{commit}` under `GitRule::Workshop`; then the `officina/<name>` branches imported from that template's runs in the last 7 days that still exist, each with its parent run); the default, the first listed base; the count of uncommitted changes (`status --porcelain=v1 -z --untracked-files=normal`); mounts with their state; the allow-list (`CLAUDE_CODE_HOSTS` then the project's); the image tag, short id and build time; minutes and budget; the credential's kind; readiness, every side-effect-free check of AC 4 shown as its `LaunchRefusal`; `plan_sha256` (story 6.6). The collector supplies the stored facts (catalogue, registry rows, cards); the git, engine and credential-presence calls run on thread `workshop`, and the result returns as an `AuthorRequest` without deadline (review F18). `EditCard::Base(choice)` issues a new card with the same `seq` (D-135, D-215); the base `<select>` offers the closed list only. Proof: core `crates/officina-core/src/orders/card.rs::tests::{a_workshop_card_carries_its_facts, the_first_base_is_the_default, an_imported_branch_names_its_parent, a_base_outside_the_list_is_refused, edit_base_keeps_the_seq}`; host `crates/officina-host/src/workshop/launch.rs::tests::{tips_and_uncommitted_count_come_from_git, imported_bases_older_than_7_days_are_not_offered}` (real git fixture, D-23); CLI `crates/officina/tests/watch.rs::the_collector_never_spawns_docker` extended: the fake engine's and the logging git's logs show no call from the collector thread while a workshop card is issued.
2. **The credential** (AD-105, AD-36, D-29, D-243). `[workshop] auth` picks `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`. The value is the generic credential `officina:workshop`, read through story 2.11's `CredentialStore` into 2.11's `Secret`, dropped after use (no new type, review F22): at launch for the worker's `create` and the run's needles (AC 3), and for presence checks that drop it at once; tests inject a `CredentialStore` as an argument (D-86's pattern), no environment variable overrides the real source. The engine's environment rule (D-206) sets `<NAME>=<value>` in the environment of that one `docker.exe` child, while the vector carries `--env <NAME>` alone. Proof: `compile_fail` doctests asserting `Secret` has no `Display` and no `Serialize`; 2.11's `secret_debug_is_redacted` kept; CLI `crates/officina/tests/workshop_launch.rs::{the_credential_name_reaches_only_the_worker_create, the_credential_value_is_in_no_argument_and_no_log}` (a seeded value; the fake engine logs names and the test searches its log and every argument for the value).
3. **Needles and the run's copy** (AD-112, D-230, D-237, review F2). `officina-core::workshop::scan` is declared here, since launch and following need it before collection does: `scan::needles(&[u8]) -> Needles` derives the value raw, its standard and URL-safe base64 at each of the three byte alignments minus the edge characters that depend on neighbouring bytes, and its lowercase and uppercase hex; `scan::find` searches each text with a plain substring search per needle, the base64 needles over the text with CR and LF removed (coreutils `base64` wraps at 76 columns, review F15); `scan::replace` puts `[credential]` in place of every occurrence. No crate. At launch the window builds the run's `Needles` from the credential it read and keeps them inside the `Secret` wrapper in the run's state for as long as it follows the run; story 6.12 replaces every untrusted text through them, and story 6.14 adds collection's scan and drops them. Proof: core `crates/officina-core/src/workshop/scan.rs::tests::{every_form_of_a_seeded_value_is_found, a_value_embedded_at_each_alignment_is_found_in_base64, a_wrapped_base64_form_is_found, replace_leaves_no_form, an_unrelated_text_is_not_found}` (forms derived programmatically from a seeded value; no test types an encoded form); host `launch.rs::tests::{needles_are_kept_for_a_running_run, needles_never_serialize}`.
4. **Launch checks** (AD-107, FR-6 as amended by amendment 6, D-207, D-231, D-236, D-247). `launch_work_order(card_id, prompt_sha256, plan_sha256)` (pointer only, D-28) runs AD-78's checks (the `claude` shim check does not apply; the catalogue check compares the global hash, D-244), then these, each a new `LaunchRefusal` variant: `workshop_off`, `workshop_stopped`, `engine_unavailable`, `image_mismatch` (the image check of story 6.8, returning the id the `create` uses), `battery_stale` (story 6.10's validity; the card offers Run escape battery), `mount_missing`, `mount_not_ignored` (`check-ignore` under the workshop rule, untracked rules included, FR-2; and `ls-tree -r --name-only <base> -- <mount>` empty, else detail `tracked`, review F3), `mount_path_unsupported` (a comma, a quote or a control character; or, detail `reparse_point`, a reparse point on the path from the project folder or a canonical path leaving it, review F11, defensive since whether Docker Desktop follows a junction is not known), `hook_program_missing` (after a fresh inventory when its key changed, story 6.9), `workshop_full`, `reviews_pending` (10 packages in `review` or `quarantined`), `credential_missing`, `project_missing`, `base_moved`, `plan_changed`. On Windows every mount comparison is case-insensitive (D-231). The checks with no side effect are evaluated first and the inventory, which starts a container, last and only when every other check passed; the refusal reported is the first failing cause in AD-107's order (review F43). Then the card is consumed. Proof: section `launch` of `tests/vectors/workshop.json` through `crates/officina-core/tests/workshop_vectors.rs::{launch_checks_report_in_ads_order, every_new_launch_refusal_has_a_case}`; core `card.rs::tests::{a_rebuilt_image_after_issue_is_plan_changed, the_inventory_runs_only_after_every_other_check_passed}`; host `launch.rs::tests::{a_force_added_file_in_a_mount_is_tracked, a_junction_on_the_mount_path_is_refused, a_mount_differing_only_in_case_is_found}`.
5. **Launch steps** (AD-107, FR-6 steps 1 and 2, D-214, D-240, D-242). On thread `workshop`; the first failure ends the launch `failed`, removes what was created (`workshop_removed`, cause `launch_failed`) and records the failing step: (1) one transaction inserts the `work_order` row (runner `workshop`, outcome `launching`) and the `workshop_run` row (state `launching`, `battery_id` the battery the check relied on, D-212); (2) `<home>/workshop/runs/<id>/in/`: `git bundle create base.bundle refs/heads/<base>` under the workshop rule, then core's `workshop::bundle::parse_header` (declared here on the first 64 KiB: v2 or v3 signature, capabilities, prerequisites, references; story 6.13 adds the package checks) finds its single reference pointing at the card's base commit (`base_moved`) and the file at most 1 GiB (`base_too_large`); `prompt.txt`; `plan.json`; the stop flag read again; (3) both networks, the volume, the gateway (create, connect), the worker (create, with the credential), `cp` of `in/` into the worker's volume (or, if the gate 1 entry recorded a failed copy, `in/` as a read-only bind mount, D-203); the stop flag and story 6.17's latch read again; start the gateway, then the worker; (4) the clock skew measured from `info`'s `SystemTime` and stored in the facts (a diagnostic, D-242); state `running`, `work_order` outcome `started`, one `workshop_started` line (AD-120's fields plus `battery_id`) with every step's outcome; never a `work_order_launched` line (D-214). AD-81's binding skips rows whose runner is `workshop`; v0.5's 2-minute `launching` sweep (D-136) skips them too, their `launching` rows following AD-109's reconciliation only (D-240, review F19); the subject is filed when the run reaches `running`. Fake engine modes: `create`, `start`, `cp` in, `network` and `volume` calls counted per role, with a configurable `start` latency. Proof: CLI `crates/officina/tests/workshop_launch.rs::{zero_creates_and_starts_before_the_click, one_gateway_and_one_worker_after_the_click, created_vectors_equal_the_golden_rebuild, a_failed_step_removes_what_was_created, the_stop_flag_between_steps_ends_the_launch, a_launch_writes_workshop_started_only, binding_skips_workshop_rows, a_double_click_launches_once}`; `crates/officina/tests/watch.rs::a_slow_workshop_launch_is_not_swept` (a fake engine delay past 2 minutes on a simulated clock); core `relay/journal.rs::tests::{workshop_started_round_trips, workshop_removed_round_trips}` (this story is `workshop_removed`'s first writer, D-249); section `headers` of `tests/vectors/bundle.json` (formatter-exempt, byte fixtures made by real git) through `crates/officina-core/tests/bundle_vectors.rs::header_cases_match`.
