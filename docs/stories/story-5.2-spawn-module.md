# Story 5.2: One spawn module: vector kinds, environment, golden vectors and the lint

**Status:** Approved

## Story

As the author about to let Officina start sessions for the first time,
I want every `claude` process Officina creates to come from one host module, built from a typed vector that core fixes and a golden file pins, with the parent session's identity stripped from its environment and my own settings kept where my sessions need them,
so that "no path launches a session except the window's" is a property of the code and the shipped binary, no child of Officina inherits a session's inbox, and a session Officina starts behaves as one I start.

## Acceptance Criteria

1. **Core vectors** (AD-79, D-128). `officina-core::spawn` declares `VectorKind` with `closed_enum!` holding `Agents`, `Version`, `Attach` and `TriageCall`, `VectorKind::is_launch()` as an exhaustive `match`, and `ClaudeVector { kind, args, cwd, console, stdin, capture, deadline_ms, env_set, env_remove }` with private fields and getters; `CwdRule` (inherited, the binary's folder, a fixed Officina directory, a given folder), `Console` (none, new), `StdinRule` (null, console, data) and `Capture` (stdout cap, stderr cap) are closed enums or plain structs. Builders: `spawn::agents()`, `spawn::version()`, `spawn::attach(&BackgroundId, config_dir)`, `spawn::triage_call(model, schema, config_dir)`. `BackgroundId::parse` wraps `focus::is_valid_attach_id`, the one copy of the rule. Proof: core `crates/officina-core/src/spawn.rs::tests::{background_id_follows_the_attach_rule, attach_takes_only_a_parsed_background_id, is_launch_names_every_kind}`; a `compile_fail` doctest on a `ClaudeVector` struct literal outside the module.
2. **Environment** (AD-80 as D-128 reads it, E18; review F1, F4, F13). `SESSION_ENV_REMOVED` lives in `officina-core::spawn`, holds E18's names, and replaces `registry::triage_call::TRIAGE_ENV_REMOVED`. One exhaustive `match` per kind gives its rule: every kind removes `SESSION_ENV_REMOVED`; the contained kinds (here `TriageCall`) also remove every `OFFICINA_*` name, while the session kinds (here `Agents`, `Version`, `Attach`) keep the base environment's `OFFICINA_*` names unchanged; every kind but `Orchestrator` (story 5.16) removes `CLAUDE_CODE_DISABLE_AGENT_VIEW`; every kind sets `NoDefaultCurrentDirectoryInExePath=1` and, when the floor declares one, `CLAUDE_CONFIG_DIR`. On Windows a removal matches names ignoring ASCII case. Proof: core `spawn.rs::tests::{every_kind_removes_the_session_variables, every_kind_sets_the_exe_path_rule_and_the_config_dir, only_contained_kinds_drop_the_officina_prefix, agent_view_is_removed_on_every_kind_but_the_orchestrator}`, each iterating `VectorKind::ALL`; CLI `crates/officina/tests/spawn.rs::{seeded_session_variables_never_reach_the_child, session_kinds_keep_the_authors_officina_settings, contained_kinds_drop_the_officina_prefix}` (the base environment holds every name of `SESSION_ENV_REMOVED`, iterated from the constant, one of them in mixed case, plus `OFFICINA_HOME`, `OFFICINA_FLOOR`, `OFFICINA_NO_EXCERPTS` and `CLAUDE_CODE_DISABLE_AGENT_VIEW=1`; for every kind the fake claude's log shows exactly the names its rule keeps).
3. **Golden vectors** (AD-79, AD-95 spawn row). `tests/vectors/spawn.json` (formatter-exempt) holds at least one case per kind: inputs, then the expected arguments, directory rule, console, stdin, capture, deadline, variables set and removed. Proof: core `crates/officina-core/tests/spawn_vectors.rs::{every_case_matches_its_builder, every_kind_has_a_case}` (the second iterates `VectorKind::ALL`); CLI `spawn.rs::every_kind_reaches_the_fake_claude_as_its_golden_vector` (the logged `argv` array compared element by element, the working directory and the variable names, against the same file).
4. **Host execution** (AD-73, AD-6 and AD-15 as amended, D-97, D-128; review F10). `officina-host::spawn` holds the resolution of AD-6 (moved from `claude.rs`, which goes), `ResolvedClaude { path, extension }` and `execute(&ResolvedClaude, &ClaudeVector, &BaseEnv) -> Result<SpawnOutcome, SpawnError>`. Captured kinds run against their deadline and caps and keep draining both streams past them. The job rule per kind, one exhaustive `match`: `Agents` and `Version` (and `Logs` later) keep today's job, terminated with its tree on timeout; `TriageCall` (and `ReviewCall` later) run in a kill-on-close job assigned after the spawn; `WorkOrder` (story 5.5) runs in no job and its deadline kills the direct child only; console kinds run in no job. Console kinds start with `CREATE_NEW_CONSOLE`, are not waited on, and return the pid with its creation time; every other kind gets `CREATE_NO_WINDOW`. `platform::windows::open_attach_console` moves in as the `Attach` path. The collector's agents refresh, the version check and canary, doctor, focus and the triage runner call `execute`. Proof: host unit `crates/officina-host/src/spawn.rs::tests::{creation_flags_follow_the_console_rule, the_job_rule_names_every_kind}`; CLI `spawn.rs::{a_captured_kind_is_capped_and_both_streams_drain, the_deadline_ends_a_captured_kind_and_its_tree, a_console_kind_is_not_waited}`; the existing `watch.rs`, `board.rs`, `triage.rs` and focus tests stay green unchanged.
5. **A console for console kinds** (review F11). Fake claude mode `interactive` logs whether its stdin and stdout are a console (`GetConsoleMode` succeeds on them) and exits 0. Proof: CLI `spawn.rs::a_console_kind_gets_a_console` (`Attach` here; `Answer` and `Orchestrator` join it in their stories).
6. **Executables only** (AD-79, AD-15 as amended by section 3, D-128; review F28). On Windows `Agents` and `Version` accept an `.exe`, and a `.cmd` or `.bat` through `cmd.exe /d /c` as today; every other kind accepts only an `.exe`, whatever `OFFICINA_CLAUDE_BIN` names, and refuses anything else before spawning; a focus on a background card through a refused binary reports a failure that names the copy-attach-command path. Proof: CLI `spawn.rs::a_non_exe_claude_is_refused_for_every_kind_but_agents_and_version` (iterates `VectorKind::ALL` with a `.cmd` wrapper and a `.com` copy of the fake claude; the log stays absent for refused kinds); host `crates/officina-host/src/focus.rs::tests::attach_through_a_shim_fails_with_the_copy_hint`.
7. **Authority split** (AD-73, AD-21 as amended, D-128, D-9; review F5). The launch half (`TriageCall` here; `WorkOrder`, `Answer`, `ReviewCall`, `Orchestrator` join later) compiles under `window-authority`, its error type carrying `AUTHORITY_MARKER`; `execute` built without the feature refuses every kind whose `is_launch()` is true before any process starts, with an error that carries no marker; the triage runner moves under the feature. Proof: host unit `crates/officina-host/src/spawn.rs::tests::execute_refuses_every_launch_kind_without_the_feature` (compiled only under `#[cfg(not(feature = "window-authority"))]`; iterates `VectorKind::ALL` through a resolver pointing at the fake claude, whose log must stay absent); a CI step on both the `core-linux` and `windows` jobs running `cargo test -p officina-host --lib spawn` alone, so no other package turns the feature on; the CI step "officina holds no authority" (marker absent from a fresh `-p officina` build, present in `officina-app.exe`).
8. **The lint** (AD-73, D-128; review F18). `crates/officina-host/clippy.toml` lists `std::process::Command::new` in `disallowed-methods` with a reason; `src/` holds exactly three `#[expect(clippy::disallowed_methods, reason = "...")]` sites: `spawn`, `relay::run` and `git`; story 2.10's WSL probe in doctor (`wsl.exe --exec /usr/bin/test -x`) moves into `relay::run`, the catalogue programs' site, and doctor calls it there. Proof: the CI clippy steps; `crates/officina-host/tests/spawn_lint.rs::command_new_is_expected_in_three_modules_only` (reads every `.rs` under `src/` and compares the files holding the attribute with those three); the tests of story 2.10's WSL probe stay green unchanged.
9. **Read-only git** (AD-73, D-22, D-128, D-163). `officina-host::git` runs every `git` call with D-22's flags, `GIT_OPTIONAL_LOCKS=0` and `CREATE_NO_WINDOW`; the tree fingerprint of story 2.6 calls it, with an unchanged result. Proof: the tests of `crates/officina-host/tests/relay_tree.rs` stay green unchanged; host unit `crates/officina-host/src/git.rs::tests::every_call_carries_the_flags_and_the_lock_variable`; host integration `crates/officina-host/tests/git.rs::{a_fingerprint_leaves_a_stale_index_unchanged, without_the_lock_variable_the_index_changes}` (the first touches a tracked file's modification time so plain git would refresh the index, then compares the bytes of `.git/index` before and after; the second is the control, which proves the precondition; both skip with a printed reason when no `git` exists, D-23).
10. **Triage vector amended** (AD-51 as amended by section 3, P-23). `TriageCall` adds `--settings {"crossSessionInbound":"refuse"}` and the environment of AC 2; its golden argument vector moves from `triage_call.rs::tests::argv_is_pinned` into `spawn.json` and changes once. Proof: the `TriageCall` case of `spawn.json`; CLI `crates/officina/tests/triage.rs::argv_matches_the_golden_vector` reading `spawn.json`.
11. **Fake claude** (D-129; review F4, F12). Every call appends one line of JSON, `{"argv": [...], "cwd": "...", "env_names": [...]}`, names sorted, never a value; with `CLAUDE_CODE_DISABLE_AGENT_VIEW=1` it refuses `--bg`, `agents` and `logs` as `claude` does (S7); mode `interactive` per AC 5. Proof: CLI `crates/officina/tests/fake_claude.rs::{the_log_is_one_json_object_per_call, a_prompt_with_a_newline_stays_one_argument, agent_view_off_refuses_bg_agents_and_logs}`.
12. **Doctor** (AD-94 part A, FR-15). When `claude` resolves to anything but an `.exe`, doctor fails with one line saying that launches, answers, reviews, the orchestrator and attach are refused and the attach command can be copied; this line replaces story 3.9's triage-only `.cmd` line. Proof: host `crates/officina-host/src/doctor.rs::tests::a_non_exe_claude_fails_with_every_refused_use`.
13. **Documentation** (D-149). `CHANGELOG.md` `[Unreleased]`: under Changed, attach refuses a `claude` that is not an `.exe` (copy the attach command instead); under Security, every `claude` Officina starts drops the variables Claude Code gives a session's children, and Officina's own contained calls also drop every `OFFICINA_*` name. - Seams (D-124): this story touches v0.1's `claude.rs`, `platform/windows.rs`, `focus::is_valid_attach_id` and focus; v0.2's `relay::run` (an `expect` site and the WSL probe of 2.10) and the tree fingerprint of 2.6; v0.3's triage runner (3.9) and `registry::triage_call`. The `WorkOrder`, `Logs`, `Answer`, `ReviewCall` and `Orchestrator` kinds are not declared here: each arrives with its story and its golden case (D-128), so `every_kind_has_a_case` holds at every merge, and each joins the environment and job `match`es then.
- Why the session kinds keep `OFFICINA_*` (review F1): the hooks a session runs read `OFFICINA_HOME`, `OFFICINA_FLOOR` and `OFFICINA_NO_EXCERPTS` from their own environment, and the registered hook command carries neither home nor floor. Stripped, a work order in a guarded project would meet a gate that finds no floor and guards nothing, and its excerpts would be recorded against the author's switch. Officina's own contained calls keep the removal: they run no hook and must not reach the author's home.
- The fake claude is a binary of the `officina` crate, so every test that spawns it lives in `crates/officina/tests/` with `window-authority` through the dev-dependency, as `triage.rs` does (3.9). That is also why AC 7's proof is a host unit test run alone: every other test build has the feature on.
- `BaseEnv` is the environment the window passes from its own process at start (D-86): tests build one holding the seeded names and never call `std::env::set_var`.
- Removing by prefix (`OFFICINA_`) happens in `execute`, because core cannot list the parent's environment.
- `Attach` from the binary's folder with `NoDefaultCurrentDirectoryInExePath=1` is v0.1's rule (security audit of 2026-10-27); what changes is the executable rule. A shim install keeps the copy-attach-command action (AD-79's "gives up").
- Whether a console child of a GUI process gets its own standard handles is asserted by AC 5's test, not by this note (review F11).
- The lint test reads source text on purpose: clippy enforces the rule, the test enforces "exactly three", which no lint can.
- The backlog's Low item (a timed-out `claude agents` leaves its grandchildren) is covered by the job rule of AC 4 for `Agents` as today.
- No employer content in `spawn.json`: placeholder paths, `<UUID>`-shaped ids.
