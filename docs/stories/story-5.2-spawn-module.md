# Story 5.2: One spawn module: vector kinds, environment, golden vectors and the lint

**Status:** Review

## Story

As the author about to let Officina start sessions for the first time,
I want every `claude` process Officina creates to come from one host module, built from a typed vector that core fixes and a golden file pins, with the parent session's identity stripped from what a session kind inherits and only an allow list given to Officina's own contained calls,
so that "no path launches a session except the window's" is a property of the code and the shipped binary, no child of Officina inherits a session's inbox, and a session Officina starts behaves as one I start.

## Acceptance Criteria

1. **Core vectors** (AD-79, D-128). `officina-core::spawn` declares `VectorKind` with `closed_enum!` holding `Agents`, `Version`, `Attach` and `TriageCall`, `VectorKind::is_launch()` as an exhaustive `match`, and `ClaudeVector { kind, args, cwd, console, stdin, capture, deadline_ms, env_set, env_rule }` with private fields and getters; `CwdRule` (inherited, the binary's folder, a fixed Officina directory, a given folder), `Console` (none, new), `StdinRule` (null, console, data), `Capture` (stdout cap, stderr cap) and `EnvRule` (D-561: `Session`, the base minus removals; `Contained`, the allow list only) are closed enums or plain structs. Builders: `spawn::agents()`, `spawn::version()`, `spawn::attach(&BackgroundId, config_dir)`, `spawn::triage_call(model, schema, config_dir)`. `BackgroundId::parse` wraps `focus::is_valid_attach_id`, the one copy of the rule. Proof: core `crates/officina-core/src/spawn.rs::tests::{background_id_follows_the_attach_rule, attach_takes_only_a_parsed_background_id, is_launch_names_every_kind}`; a `compile_fail` doctest on a `ClaudeVector` struct literal outside the module.
2. **Environment** (AD-80 as D-128 and D-561 read it, the session-variables entry of story 5.1; review F1, F4, F13). One exhaustive `match` per kind gives its rule:
   - session kinds (here `Agents`, `Version`, `Attach`): the base environment minus `SESSION_ENV_REMOVED` (a constant of `officina-core::spawn` holding the session-variables entry's names) and minus `CLAUDE_CODE_DISABLE_AGENT_VIEW`; the base's `OFFICINA_*` names kept unchanged;
   - contained kinds (here `TriageCall`): exactly the base's names found in the contained allow list, which moves unchanged from `registry::triage_call` (`TRIAGE_ENV_SYSTEM`, `TRIAGE_ENV_NETWORK`, `TRIAGE_ENV_AUTH`, epic-3-decisions.md D-439) into `officina-core::spawn`, matched ignoring ASCII case; nothing else of the base;
   - every kind then sets `NoDefaultCurrentDirectoryInExePath=1` and, when the floor declares one, `CLAUDE_CONFIG_DIR`, never one inherited from the base; on Windows a removal or a match ignores ASCII case.

   Proof: core `spawn.rs::tests::{session_kinds_remove_the_session_variables, contained_kinds_take_only_the_allow_list, every_kind_sets_the_exe_path_rule_and_the_config_dir, agent_view_is_removed_on_every_session_kind, the_allow_list_is_triage_calls_unchanged}`, each iterating `VectorKind::ALL` or the constants (never a typed list); CLI `crates/officina/tests/spawn.rs::{seeded_session_variables_never_reach_the_child, session_kinds_keep_the_authors_officina_settings, contained_kinds_receive_the_allow_list_only}` (the base environment holds every name of `SESSION_ENV_REMOVED`, iterated from the constant, one of them in mixed case, plus `OFFICINA_HOME`, `OFFICINA_FLOOR`, `OFFICINA_NO_EXCERPTS`, `CLAUDE_CODE_DISABLE_AGENT_VIEW=1` and a name outside every list; for every kind the fake claude's log shows exactly the names its rule keeps).
3. **Golden vectors** (AD-79, AD-95 spawn row). `tests/vectors/spawn.json` (formatter-exempt) holds at least one case per kind: inputs, then the expected arguments, directory rule, console, stdin, capture, deadline, variables set and the environment rule. Proof: core `crates/officina-core/tests/spawn_vectors.rs::{every_case_matches_its_builder, every_kind_has_a_case}` (the second iterates `VectorKind::ALL`); CLI `spawn.rs::every_kind_reaches_the_fake_claude_as_its_golden_vector` (the logged `argv` array compared element by element, the working directory and the variable names, against the same file).
4. **Host execution** (AD-73, AD-6 and AD-15 as amended, D-97, D-128, D-562; review F10). `officina-host::spawn` holds the resolution of AD-6 (moved from `claude.rs`, which goes), `ResolvedClaude { path, extension }` and `execute(&ResolvedClaude, &ClaudeVector, &BaseEnv) -> Result<SpawnOutcome, SpawnError>`. Captured kinds run through `process::run_contained` (epic-3-decisions.md D-436), against their deadline and caps, and keep draining both streams past them. The job rule per kind, one exhaustive `match`, as `run_contained` sets it per call today: `Agents` and `Version` (and `Logs` later) keep their short grace and their job, terminated with its tree on timeout; `TriageCall` (and `ReviewCall` later) run in a kill-on-close job assigned before the prompt is written, or are stopped (D-436); `WorkOrder` (story 5.5) runs in no job and its deadline kills the direct child only; console kinds run in no job. Console kinds start with `CREATE_NEW_CONSOLE`, are not waited on, and return the pid with its creation time; every other kind gets `CREATE_NO_WINDOW`. `platform::windows::open_attach_console` moves in as the `Attach` path. The collector's agents refresh, the version check and canary, doctor, focus and the triage runner call `execute`. Proof: host unit `crates/officina-host/src/spawn.rs::tests::{creation_flags_follow_the_console_rule, the_job_rule_names_every_kind}`; CLI `spawn.rs::{a_captured_kind_is_capped_and_both_streams_drain, the_deadline_ends_a_captured_kind_and_its_tree, a_console_kind_is_not_waited}`; the existing `watch.rs`, `board.rs`, `triage.rs`, `process.rs` and focus tests stay green unchanged.
5. **A console for console kinds** (review F11). Fake claude mode `interactive` logs whether its stdin and stdout are a console (`GetConsoleMode` succeeds on them) and exits 0. Proof: CLI `spawn.rs::a_console_kind_gets_a_console` (`Attach` here; `Answer` and `Orchestrator` join it in their stories).
6. **No shim, for any kind** (AD-79, AD-15 as amended by section 3, D-128 as amended by D-562; review F28). Every kind accepts only an `.exe` and refuses anything else before spawning, whatever `OFFICINA_CLAUDE_BIN` names, as v0.3 already does for `claude agents`, `--version` and the triage call (D-436); resolution still finds a shim, so doctor and the board say why; a focus on a background card through a refused binary reports a failure that names the copy-attach-command path. Proof: CLI `spawn.rs::a_non_exe_claude_is_refused_for_every_kind` (iterates `VectorKind::ALL` with a `.cmd` wrapper and a `.com` copy of the fake claude; the log stays absent); host `crates/officina-host/src/focus.rs::tests::attach_through_a_shim_fails_with_the_copy_hint`; the existing shim tests of `claude.rs` move to `spawn` unchanged in meaning.
7. **Authority split** (AD-73, AD-21 as amended, D-128, D-9; review F5). The launch half (`TriageCall` here; `WorkOrder`, `Answer`, `ReviewCall`, `Orchestrator` join later) compiles under `window-authority`, its error type carrying `AUTHORITY_MARKER`; `execute` built without the feature refuses every kind whose `is_launch()` is true before any process starts, with an error that carries no marker; the triage runner moves under the feature. Proof: host unit `crates/officina-host/src/spawn.rs::tests::execute_refuses_every_launch_kind_without_the_feature` (compiled only under `#[cfg(not(feature = "window-authority"))]`; iterates `VectorKind::ALL` through a resolver pointing at the fake claude, whose log must stay absent); a CI step on both the `core-linux` and `windows` jobs running `cargo test -p officina-host --lib spawn` alone, so no other package turns the feature on; the CI step "officina holds no authority" (marker absent from a fresh `-p officina` build, present in `officina-app.exe`).
8. **The lint** (AD-73, D-128 as amended by D-562; review F18). `crates/officina-host/clippy.toml` lists `std::process::Command::new` in `disallowed-methods` with a reason; outside `#[cfg(test)]` modules, `src/` holds exactly three `#[expect(clippy::disallowed_methods, reason = "...")]` sites: `spawn` (what `claude.rs`, `platform/windows.rs` and `registry/triage.rs` spawn today), `relay::run` (`relay/run/spawn.rs`, and story 2.10's WSL probe, `relay/doctor.rs`'s `wsl_probe_command`, which moves there and doctor calls) and `git` (`relay/tree.rs`'s call). Test modules inside `src/` (`process.rs`, `relay/gate.rs`, `relay/tree.rs`, `relay/doctor.rs` today) carry their own `expect` and are not counted. Proof: the CI clippy steps (`--all-targets`); `crates/officina-host/tests/spawn_lint.rs::command_new_is_expected_in_three_modules_only` (reads every `.rs` under `src/`, skips `#[cfg(test)]` modules, and compares the files holding the attribute with those three); the tests of story 2.10's WSL probe stay green unchanged.
9. **Read-only git** (AD-73, D-22, D-128, D-163). `officina-host::git` runs every `git` call with D-22's flags, `GIT_OPTIONAL_LOCKS=0` and `CREATE_NO_WINDOW`; the tree fingerprint (`relay/tree.rs`, story 2.6) calls it, with an unchanged result. 10. **Triage vector amended** (AD-51 as amended by section 3, P-23, D-561). `TriageCall` adds `--settings {"crossSessionInbound":"refuse"}` and takes the contained rule of AC 2; its golden argument vector moves from `registry::triage_call`'s `argv_is_pinned` into `spawn.json` and changes once; `environment_is_an_allow_list_derived_from_the_constants` moves with the lists.
