# Story 8.10: Worker admission in core (Slice B)

**Status:** Approved

## Story

As the author whose workers read text that others can shape,
I want every worker request decided by one pure function, in a fixed order, from my approved catalogue, the run's own record and the request's bytes alone, refusing any write, any action my template did not list, any value a program could read as code, and any dry run aimed outside my scope,
so that nothing a worker writes can choose the run, the project, the folder, a production target or a command, and each refusal has a name, a vector case and a test that fails when its check is skipped (FR-7).

## Acceptance Criteria

1. **Entry condition** (P-72, D-1301, D-1313). 8.3, 8.5 and 8.9 have merged, so v0.6's Slice A has closed (6.20); no v0.7 story is a condition. Proof: the sprint status.
2. **The facts** (AD-158, D-409, D-425, review F9). Core `worker::RunRelayFacts` holds what admission reads: the run's id, state and deadline, its project, the plan's `relay_actions` and catalogue hash, `LaunchInputs` (the approved snapshot, the validated relay floor, the floor's path, the system directory), the current floor's hash, both stop flags as read (`clear`, `set`, `unreadable`) and the limiter. It is built from the run's plan, its row and the floor, never from `work_order.source` or a grant, and holds no field naming who launched the run. Proof: core `crates/officina-core/src/relay/worker.rs::tests::facts_hold_no_launcher` (a destructuring `let` with no `..`, so a new field fails the build until this test is read again); review in the QA report (D-425).
3. **Admission** (AD-158, FR-7 as amended by amendment 8, D-417, D-426 to D-429). `worker::admit(&MailboxLine, &RunRelayFacts, now_ms) -> (Admission, Limiter)` (the limiter's next state, review F31), the first failing step refusing with its `WorkerRefusal`: 1 every `MailboxLine` is taken: a mailbox `refused` line maps to `oversized`, `not_utf8` or `read_deadline` (review F4), a `request` line at or below the highest `seq` seen is dropped and counted (review F17), the line parses as one request (`malformed`) within its size (`oversized`), a `--list` request is answered here (`Listed` with the list text); 2 the limiter (`busy`, `too_soon`, `run_cap`, `not_live`); 3 both stop flags, set or unreadable (`stopped`); 4 the current floor's hash equals the approved one and the plan's (`catalogue_changed`); 5 the action is in the approved catalogue and the run's project lists it (`not_listed`); 6 it is not a write (`worker_write`), whatever its class, target or scope; 7 it is in the plan's `relay_actions` (`not_listed`); 8 parameters through `run::launch_for` with AD-30's rules (`missing_parameter`, `unknown_parameter`, `invalid_value`), then an absolute value, then a value holding an entry of `WORKER_VALUE_REFUSED` (D-426, review F1), each `invalid_value` with no echo; 9 a dry run, judged by D-427 (review F2): every write of the approved catalogue whose `check` is the requested action, whichever project lists it, with `judge(write, values, run_project, Enforcement::Worker)` in free and guarded projects alike (`order_required` with its `OutOfScopeCause`, `target_not_a_name` included, D-428), the writes with a targets action making the admission `ResolveThen` with one entry per such write (review F13). Then `Admission::Run { plan: relay::run::RunPlan, relay_seq }`. `WorkerRefusal` is a `closed_enum!` exported to TypeScript, seeded by these steps plus `check_required`, `abuse` and `journal_unavailable` (8.11's refusal when the run's `run_started` cannot be appended, D-1307); from then on `ALL` and `admit`'s order are the list. Proof: section `admit` of `tests/vectors/worker_relay.json` through `crates/officina-core/tests/worker_relay_vectors.rs::{admit_cases_match, every_worker_refusal_has_a_case, refusals_are_checked_in_their_order, a_write_of_each_class_is_worker_write, a_dry_run_in_a_free_project_is_judged, a_check_listed_by_a_project_without_its_write_is_judged, a_shared_check_across_projects_is_judged, a_dry_run_shared_by_two_writes_needs_both_in_scope, a_shared_check_resolves_every_writes_targets, a_host_pattern_target_is_order_required}` (the second iterates `WorkerRefusal::ALL`); `crates/officina-core/tests/typescript_bindings.rs::committed_bindings_match_the_rust_types` (review F29).
4. **Blocking property** (AD-165, AD-148's pattern). For each `admit` case expecting `Run` and each `WorkerRefusal` a step can give, the test's exhaustive `make_fail(refusal, &mut facts_or_line)` makes that one condition fail, and `admit` must refuse with it. Proof: `worker_relay_vectors.rs::admit_blocking_property`.
5. **The request and its values** (AD-157, AD-30, D-417, D-426; review F1, F31). A request's `argv` is the action then `name=value` items split on the first `=`; an item without `=`, a repeated name, an empty name, a non-string item or a missing action is `malformed`; values are untrusted bytes checked by AD-30, the absolute-path rule and `WORKER_VALUE_REFUSED`, refused, never echoed, in the refusal detail. The `request` cases for `WORKER_VALUE_REFUSED` are derived by iterating the constant, one case per entry placed first, in the middle and last of a value the action's pattern (`.+`) otherwise admits. Proof: section `request` of `worker_relay.json` through `worker_relay_vectors.rs::{request_cases_match, an_item_without_equals_is_malformed, every_refused_value_entry_is_invalid_value, a_refusal_detail_never_holds_the_value}` (the third iterates `WORKER_VALUE_REFUSED`).
6. **The limiter** (AD-158, D-417, D-429; review F4, F17, F31). `worker::Limiter`, a pure state machine per run: one request in flight (`busy`, from admission until its answer frame, never folded, cleared by a restart); 2 s since the previous request line whatever its outcome, mailbox refusals included (`too_soon`); fewer than 120 request lines (`run_cap`); the run `running` with at least 5 s before its deadline (`not_live`); the highest `seq` seen; the count of refusals toward `ABUSE_REFUSALS`, every `WorkerRefusal` but `abuse` and those `WorkerRefusal::is_host_side()` marks counted (one exhaustive `match`, true only for `journal_unavailable`, the host's failure, not the worker's, D-1307), the 20th refusing `abuse`. `Limiter::fold(lines)` rebuilds it from the run's `worker_relay` lines and equals the state `admit` returned after the same lines. Proof: section `limiter` of `worker_relay.json` through `worker_relay_vectors.rs::{limiter_cases_match, the_twentieth_refusal_is_abuse, journal_unavailable_does_not_count_toward_abuse, twenty_not_utf8_connections_end_the_run, a_mailbox_refusal_counts_as_a_request_line, a_replayed_seq_is_dropped, busy_is_not_folded, a_fold_from_lines_equals_the_live_state}`.
7. **After a resolution** (AD-158, AD-153, D-427). `worker::after_targets(&[(write, names_or_failure)], ...)` gives `Run` only when every write's resolution is in scope, else `order_required` with `host_not_in_scope` or `targets_failed` for the first that is not, using `scope::after_targets`. Absent when the gate 1 entry left the resolver unbuilt (D-403). Proof: section `admit` cases with names through `worker_relay_vectors.rs::{after_targets_cases_match, one_write_out_of_several_refuses}`.
8. **The list text** (AD-157). `worker::list_text(&RunRelayFacts)` lists the run's relay actions with their parameter names and rules from the approved snapshot, as `officina run --list` does for a session. Proof: core `worker.rs::tests::list_text_shows_only_the_runs_relay_actions`.
9. **Cause texts** (AD-163, D-433, review F21). `app/src/lib/relay-text.ts` holds exhaustive `Record<OutOfScopeCause, string>`, `Record<ScopeStanding, string>` and `Record<WorkerRefusal, string>`, so a new Rust variant fails `pnpm check`; Slice B shows `order_required` causes whether or not Slice A is built. If 8.7 merged first and created the first two, this story keeps them and adds the third. Proof: Vitest `app/src/lib/relay-text.test.ts > every out-of-scope cause and standing has a text`, `> every worker refusal has a text`.
10. **Mutant** (AD-165, D-148, D-422, D-1303). Core feature `mutant-worker-scope-skip` skips step 9; it compiles with `--no-run` and fails on a named `admit` case; 8.12 adds a named CLI flow to the same mutant. Proof: the `mutants` job replayed by the local gate (D-1303).
11. **Documentation** (D-423). `CHANGELOG.md` `[Unreleased]` under Added: worker admission. README "Relay scope and workers (v0.8, in progress)": what a worker may ask for, described in families with `WorkerRefusal` named, never listed; that a worker's values are refused when a program could read them as code, `WORKER_VALUE_REFUSED` named; that scope binds a worker's dry run in free and guarded projects alike, against every write that names it. Proof: review.
