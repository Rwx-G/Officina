# Story 1.4: Classification and board

**Status:** Approved

## Story

As the author,
I want every session placed in exactly one column by a pure, vector-tested function,
so that the board says "needs you", "your turn", "working" or "done" only when it is true, and "unknown" otherwise.

## Acceptance Criteria

1. **Gate (AD-11, R4).** Before any classification code: run `/clear` in an interactive session on the workstation and record in `docs/research-notes.md` (new entry E9) whether `claude agents --json` shows the new `sessionId` for the same `pid`. Proof: manual observation, research notes entry cited in Completion Notes.
2. If the gate fails, the fallback of AD-11 is implemented: the hook records `claude_pid` (first `claude.exe` ancestor via the toolhelp snapshot) and `build_board` re-points a live card on a `SessionStart` with `source` in the re-pointing set, matching `claude_pid` and `cwd`. Proof: vector cases for re-pointing, plus host test `crates/officina-host/tests/process_tree.rs::first_claude_ancestor_of_a_fake_claude_child` (Windows only). If the gate holds, this AC is closed as "not needed" with the E9 reference.
3. `core::classify` implements FR-6 precedence and the AD-11 additions; `core::build_board` assembles cards, card keys (AD-11), excerpts and `last_event_at_ms` from the events of the card's current `sessionId`. Proof: `crates/officina-core/tests/vectors.rs::replays_classification_vectors` over `tests/vectors/classification.json` (AD-14).
4. The vector set covers: every column, every badge, every documented `status`, `state` and `SessionEnd.reason` value, the `Notification` fallback (only with `status` absent, only when newer than the last `UserPromptSubmit` and `Stop`), ended-session reconstruction including superseded and `other`, the 24 h Done window, the orderings of AD-11, and unknown or missing values landing in Working with the `unknown` badge, never in Done. Proof: `vectors.rs::vector_set_covers_every_enum_value`, which iterates the enums (AD-14) and fails when a value appears in no case.
5. The enums iterated by AC 4 cannot silently grow: each exposes its variant list through a constant guarded by an exhaustive `match` in a test, so a new variant fails to compile until the list includes it. Proof: unit tests `board::tests::column_variants_are_complete` and equivalents for `Badge` and the parsed status, state and reason enums.
6. Projects are derived from the last segment of `cwd` when no floor is given; `build_board` takes an optional floor so story 1.10 plugs in without changing the signature. Proof: vector cases with distinct cwd leaves.
7. `Board` and `Card` carry the fields AD-13 outlines that exist in slice A (schema, generation time, floor name, stale, waiting count, columns, diagnostics including skipped event lines, `done_window_ms`). Quota and contract sections are added by stories 1.9 and 1.11. Proof: unit test `board::tests::board_serializes_with_absent_fields_omitted`.
8. TypeScript types are generated by `ts-rs` behind the `ts` feature into `app/src/lib/generated/`, committed, ignored by ESLint and any formatter, and CI regenerates and fails on `git diff --exit-code app/src/lib/generated` (AD-13). Proof: CI step on the `windows` job.
9. The vector file is exempt from every formatter (derived-not-transcribed rule) and holds only hand-written, redacted data built from the shapes of E1 and E2. Proof: review; the ignore entries are present in each formatter config that exists.

## Dev Notes

- Rules: FR-6, FR-7, glossary "Card key". Decisions: AD-11 (precedence additions, card keys, gate, reconstruction, Done window, ordering), AD-13 (Board contract, ts-rs), AD-14 (vector set and staleness test). Facts: E1 (agent fields and values), E2 (hook payloads and `SessionEnd.reason`).
- E1 verifies `status: waiting` and `waitingFor` only on background sessions. The interactive "waiting on a permission prompt" shape in the AD-14 example is documented, not observed. Mark such cases in the vector `name` as "documented shape" and observe one on the workstation during slice A; record the result in research notes.
- `status` is authoritative over hook events (FR-6). A hook event never moves a live card out of the column its `status` gives.
- The frontend does not re-implement classification (AD-13); there is no TypeScript replay of the vectors.
- `generated_at_ms` and every time in `Board` are absolute (AD-5): no "ago" strings from Rust.
- If the fallback of AC 2 is taken, the hook gains a process snapshot on every event: rerun the latency test of story 1.3 and record the delta.
