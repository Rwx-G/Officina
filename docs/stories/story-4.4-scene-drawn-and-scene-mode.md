# Story 4.4: The scene drawn, scaled, and switched on

**Status:** Approved

## Story

As the author with the window on a second screen,
I want a Scene mode that draws the workshop from the payloads, scaled to the window, moving only when a state changes,
so that I see at a glance who waits and who works where, and nothing moves while nothing happens.

## Dev Notes

- Requirements: FR-1, FR-2, FR-3, FR-7 (Board and Scene), FR-9 as amended; PRD section 7 (truthful motion). Decisions: AD-59, AD-61, AD-64, AD-65, AD-66, AD-67 (light tokens), AD-70, AD-72; addendum sections 3 and 4. Epic decisions: P-19, D-98, D-101, D-105, D-106, D-109, D-110, D-113, D-117, D-119, D-121, D-123, D-184 to D-186.
- Seams (D-98): the Relay switch (2.9) and the Subjects switch (3.5) move into `lib/view.svelte.ts` and the view formerly named Board becomes Sessions; their Playwright cases change label only. The scene's input takes the relay and registry stores' views (`lib/relay.svelte.ts` of 2.7, `lib/registry.svelte.ts` of 3.5) or `null`; the relay is unused until 4.7. v0.2's banners (2.7) stay above the sessions area. A registry view is pushed in e2e through story 3.5's `__officinaPushRegistry`.
- Layout from story 4.3: `$derived(layoutScene(input, memory.current))`, where `memory.current` is the plain variable of D-184, not reactive state: the derived depends on the payloads only. The effect that calls `memory.commit(layout.memory)` replaces that variable and writes storage on change, so it never re-runs the layout; a reactive memory would loop (`effect_update_depth_exceeded`). `memory.load(board)` runs before the first layout of the run.
- Svelte writes nothing to the DOM when a re-render yields equal values; the truthful-motion case proves it for the whole subtree. Keep every attribute a pure function of the layout: no counters, no ids from a sequence, no inline styles computed from time. The halo's style is the one written at mount by the action (4.2). `data-scale` and the transform are written together, and `openScene` waits for them (D-185), so the observer never sees the first write; `expect.poll`, never `requestAnimationFrame`, which `page.clock` fakes.
- D-109: Svelte transitions use the Web Animations API, which the CSS reduced-motion rule does not stop, and are skipped only when duration and delay are both 0. D-186: Svelte's `flip` cannot move SVG figures (it divides by `clientWidth`, 0 below the outer `<svg>`), hence `seatMove`; keep the previous logical point per key in a plain map to compute the delta.
- Layers 1 and 3 are separate SVGs, so no element travels between them (AD-64): a figure leaving the antechamber for its desk fades out in layer 3 and in at its desk in layer 1.
- Plaques and the register are HTML in `<foreignObject>` (D-106): CSS ellipsis caps plaques at 140 px (R28); text at 12 px bold or more, as in the mock.
- The prototype's `render.mjs` and `tokens.mjs` are the drawing and the light values to port (`epic-4-decisions.md` says where); after the move `app.css` is the only copy of the tokens (D-117). The lamp and the dials (4.7) leave their wall spots bare here.
- jsdom has no `matchMedia`, `ResizeObserver` or `Element.animate`: one `setupFiles` module stubs them, reduced motion on by default so Svelte never calls `animate` in component tests; `motion.test.ts` overrides `matchMedia` per case.
- The baseline comparison is the owner's gate for the drawing (R27, D-119); an earlier review of the mock, if any, is in 4.3's notes. Tell the owner before the comparison: the mock's (b) and (c) panels draw a lamp and an archive count from hand-written relay and registry payloads, while these light baselines have no lamp and show "Done, 24 h" (review F38).
- `openScene` stores the view state through `addInitScript` only when `localStorage["officina.view.v1"]` is absent, so a reload in a persistence case keeps what the test changed (review F37); it installs the clock at the board's `generated_at_ms` as `openBoard` does.
