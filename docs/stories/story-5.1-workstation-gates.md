# Story 5.1: Workstation gates and the research notes they feed

**Status:** Approved

## Story

As the author whose orchestrator, work orders and answers rest on Claude Code behaviours nobody has yet observed interactively,
I want the gates of PRD section 8 and gate 8 of its addendum run on my workstation, each recorded as a research-notes entry that says what was seen and who ran it,
so that every later story implements an observed fact, a failed gate reshapes its FR before code is written (FR-0), and I know whether Claude Code's auto mode lets the relay work before I decide to switch to it.

## Acceptance Criteria

1. **The session-variables entry** (AD-80, D-125, D-560; agent). From its own Bash tool, the developer agent lists the names of the variables its Bash child holds that neither the user nor the machine environment block holds (PowerShell `[Environment]::GetEnvironmentVariables('User')` and `('Machine')`), keeps those Claude Code sets per session (session identity, project dir and pid, entrypoint and nesting markers, messaging socket and token) and lists apart what Git Bash and the shell add; then it starts, from an empty scratch folder, a print-mode `claude -p` with `--strict-mcp-config --mcp-config` naming a stub stdio server that logs the names of its own environment variables, and adds the Claude Code names the server holds (E11: `CLAUDE_PROJECT_DIR`, `CLAUDE_PID` and others), since `officina mcp` spawns from that environment. The entry is the union; names only, never a value (D-125, review F46). It takes the next free number when written (D-560: E18 is story 2.17's). Proof: the research notes entry with the Claude Code version; story 5.2's `SESSION_ENV_REMOVED` cites it.
2. **E19, `--bg`, trust and agent view** (addendum section 1, items 1 to 3; agent; no model turn). In an empty scratch folder outside the repository, with every name of the session-variables entry and every `OFFICINA_*` name removed from the child: `claude --help` still shows `--permission-mode` with `dontAsk`, `--disallowedTools`, `logs` and the `--bg` with `--resume` sentence ("starts a copy ... when the session is already running"); `CLAUDE_CODE_DISABLE_AGENT_VIEW=1 claude --bg --name probe -- x` prints the disabled line, exits 1 and starts nothing; `claude --bg --name probe -- x` in that untrusted folder exits 1 with `Workspace not trusted`; `CLAUDE_CODE_DISABLE_AGENT_VIEW=1 claude agents --json --all` is recorded (exit code, whether it lists sessions), since the orchestrator's MCP server inherits that variable (D-125, review F4). `claude agents --json --all` without the variable is identical before and after. Proof: research notes entry E19.
3. **Gate 2, the bare `--`** (E20; AD-96 row 2, PRD question 2 as amended by amendment 13). The owner trusts a scratch git repository once (`claude` run interactively in it) and adds to its `.claude/settings.local.json` a `UserPromptSubmit` hook that dumps only `prompt` to a file. Then, for each of the four cases of addendum section 1 item 5 (a leading dash with quotes, an escaped quote, a newline and a tab; `%`, `^`, `&`, `|`, `<`, `>`, `!`, `$` and `*`; accented letters, backslashes and a trailing backslash; inner `--`, `--bg` and `--model` text), passed as one argument by MSVC quoting: the agent runs `claude --bg --name probe-<n> -- <case>` as the window will, with stdin null, stdout and stderr piped and no console, and records its stdio and whether `claude --bg` returns with its output pipes closed or leaves a process holding them, with the time until they close (review F9 c, F10); the owner runs `claude --resume <session id> -- <case>` on that session from a new console whose working directory is the `claude` binary's folder, as the `Answer` vector does, and the folder is recorded (review F9 a). Pass: the hook receives each case byte for byte, per form. E20 also records items 4 and 5 (print mode) from the addendum. Proof: research notes entry E20, one result per form and case; D-127 says what each outcome changes.
4. **Gate 3, resume delivery** (E21; AD-96 row 3; owner). In the same repository: `claude --bg --name probe -- "Reply with the word ready."`; wait for `idle` and `done`; from a new console whose working directory is the `claude` binary's folder (recorded, review F9 a) `claude --resume <session id> -- "Reply with the word delivered."`; record the console line, `claude agents --json` before and after (one row, `busy` within 30 s, no copy). Then make the session ask a question through `AskUserQuestion` and resume again: `Your prompt was not sent to it`, no state change. Pass: both. Proof: research notes entry E21; D-127.
5. **Gate 4, work order permissions** (E22; AD-96 row 4 by hand, D-126; owner). In one free and one guarded project the owner names, the exact `WorkOrder` vector of AD-79 (`claude --bg --name probe-<n> -- <prompt>` with `--` per E20, working directory the project folder, the floor's `CLAUDE_CONFIG_DIR`, `NoDefaultCurrentDirectoryInExePath=1`, the session-kind environment of D-128: the session-variables entry's names and `CLAUDE_CODE_DISABLE_AGENT_VIEW` removed, the owner's `OFFICINA_*` names kept), the agent writing the exact command line for the owner's console; the prompt creates `officina-probe.txt`, runs `git status`, and lists the names (never the values) of the environment variables its Bash sees, which shows whether a `--bg` session takes the invoking process's environment or the supervisor's (review F9 e). Record `claude agents --json` over 60 s, and the `permission_mode` the probe session reports (the owner's default today, the research note's Q1). Pass: no `waiting` with `permission prompt`, and the file exists. The owner removes the file and the session. The window half of this gate closes story 5.7 (D-126, review F25), and the gate runs again once the owner switches his default mode (D-573). Proof: research notes entry E22; D-127 on failure, and on a supervisor's environment.
6. **Gate 7, `claude logs`** (E23; AD-96 row 7, D-126; agent). On gate 2's or gate 3's background session: `claude logs <id>` with stdout redirected to a file; record exit code, byte count, count of ESC bytes and elapsed time; then the same with `CLAUDE_CODE_DISABLE_AGENT_VIEW=1` (exit code and output, review F4). Exit 0 in under 2 s without the variable keeps the `Logs` kind for story 5.10; otherwise 5.10 builds neither the logs section nor the kind. The readability after stripping is judged in 5.10. Proof: research notes entry E23.
7. **Gate 1, containment half** (E24; AD-96 row 1 by hand, PRD question 1 as amended by amendment 12, D-126, D-561; owner). The agent writes, in a new empty scratch folder outside the repository, a stub stdio MCP server (any language already on the workstation, never committed) answering `server/discover` with `-32601`, then `initialize`, `notifications/initialized`, `tools/list` with one tool `briefing`, and `tools/call` with a constant text; and the exact command line of AD-89 (`--tools ""`, `--strict-mcp-config --mcp-config` naming that stub as `officina`, `--setting-sources ""`, `--settings {"crossSessionInbound":"refuse"}`, `--permission-mode dontAsk --allowedTools mcp__officina --disallowedTools SendMessage,ListAgents`, `--append-system-prompt <text>`, `--name officina-orchestrator -- <a first prompt starting with a letter>`), in a second empty folder used as the workdir, whose parent holds a marker `CLAUDE.md` the agent writes (an instruction that would show in any answer) (review F23). The environment is D-561's: exactly the names of the contained allow list (`registry::triage_call`'s three lists today) found in the owner's environment, the floor's `CLAUDE_CONFIG_DIR`, `NoDefaultCurrentDirectoryInExePath=1` and `CLAUDE_CODE_DISABLE_AGENT_VIEW=1`, nothing else; the agent writes a launcher that builds it. The owner starts it in his own console and records: whether it starts at all, and if not the missing name Claude Code names (then the run is repeated with that one name added, and the entry records it for `ORCHESTRATOR_ENV_EXTRA`, D-561); whether the trust dialog appeared; that the first prompt arrived as the first turn; `/mcp` (only `officina`); `/context` (every tool listed: only `mcp__officina__*`; and every memory file listed, the marker's included or not, D-164); `/status` (permission mode `dontAsk`); `/config` (the row "Messages from your other sessions" absent); asked to read a file, run a command and message another session, no prompt appears and nothing runs; from another interactive session, `/list-agents` and a request to message the orchestrator a unique token, recording what the sending session saw (sent, refused, not found): the token never appears in the orchestrator's transcript viewer (`Ctrl+O`) and no held-message dialog opens; when the sender found no orchestrator, the token test runs once more with the same flags minus `CLAUDE_CODE_DISABLE_AGENT_VIEW`, so the refusal itself is observed (review F9 b); `claude agents --json` lists it or not. E24 also records addendum items 6 to 8 (print mode). Pass: all of these; a memory file loaded is recorded and handled by D-164, and a missing name by D-561, neither a failure of the gate. A failure stops Slice C before story 5.15 and reopens FR-10 with the owner. Proof: research notes entry E24; the window half closes story 5.16 (D-126).
8. **Gate 8, auto mode and `officina run`** (AD-180, PRD section 9 item 8, D-572; owner, prepared by the agent). The agent prepares, outside the repository, a scratch Officina home with a floor holding one guarded scratch git repository and two actions, `check` (class `free`, a harmless read-only program) and `apply` (class `human`, `check = "check"`), approved with `crates/officina-host/examples/approve_fixture.rs`, plus the exact command lines for the owner's console (`OFFICINA_HOME` set for the probe only). In that repository, trusted once by the owner, a session started with `claude --permission-mode auto` is asked to run `officina run check` and then `officina run apply`: case a, no allow rule; case b, a narrow allow rule for `officina run` passed through `--settings` (never the owner's user settings), its exact text recorded; case c, only when b fails, an `autoMode.allow` sentence passed the same way. Per case and action: whether the classifier let the call start (for `apply`, whether its request file appeared under the scratch home's `relay/`; nobody approves it, and it expires), the classifier's reason on a block, `/permissions` (the rule kept or dropped in auto mode) and `claude auto-mode config`. Pass: `check` runs and `apply` reaches its request in case a or b. Proof: research notes entry for gate 8, numbered when written (D-560); D-573 says what each outcome ships in story 5.20.
9. **Nothing left behind** (AD-96 preamble, D-125). Every probe background session is stopped and removed (`claude stop`, `claude rm`); `claude agents --json --all` is recorded before and after each gate; scratch folders and the scratch Officina home lie outside the repository and the owner's own home; the repository's working tree changes only in `docs/research-notes.md`. Proof: each entry's before and after listings; `git status` at the end of the story.
10. **Recording rules.** Each entry says verified or documented, the Claude Code version and date, who ran it (agent or owner), the procedure, what was seen and the outcome against the pass column of AD-96 or D-572; scratch names and placeholder paths only (`CLAUDE.md` *Provided data redaction*); environment values never appear. Proof: review of `docs/research-notes.md`.
