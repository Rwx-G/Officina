# Story 6.6: Container vectors, the two networks and the run plan

**Status:** Approved

## Story

As the author who lends a container nothing but a clone, tools and one token,
I want every container Officina creates built in core from typed inputs, one builder per role, pinned by golden vectors, with the worker's environment, mounts, limits and `claude` arguments fixed there,
so that what a worker holds is a property of reviewed code, a project Dockerfile cannot change it, and the battery attacks the vector a run uses.

## Acceptance Criteria

1. **Builders** (AD-102, AD-104, D-243). Story 6.3 declared `ContainerRole` and `ContainerVector`; this story adds one builder per role, the only constructors (`compile_fail` doctest on a struct literal), and alone owns the fixed options and labels. Every role gets `--read-only --cap-drop ALL --security-opt no-new-privileges:true --init --stop-timeout 3`, `--memory-swap` equal to `--memory`, a `--pids-limit`, AD-98's log options and labels, and overrides `--entrypoint`, the command and `--user`; none ever gets `--privileged`, `--device`, `--pid host`, `--ipc host`, `--network host`, `--userns host`, another `--security-opt` or an engine socket. Each `create` names its image by id (D-207). Story 6.3's `#[cfg(test)]` vector in the `engine` section's `create` case is replaced by a builder's output. Proof: core `crates/officina-core/src/workshop/vector.rs::tests::{every_role_carries_the_fixed_options, no_role_carries_a_forbidden_option, entrypoint_user_and_command_are_always_overridden, images_are_named_by_id}`, each iterating `ContainerRole::ALL`.
2. **Networks** (AD-104, the gate 2 entry). The gateway is created on `officina-out-<id>` (a user-defined bridge holding it alone), then connected to `officina-int-<id>` (`--internal`); the worker is created on `officina-int-<id>`; `network create` and `network connect` vectors carry the run's labels. If the gate 2 entry recorded outside names resolving, the worker gets `--dns 0.0.0.0` and the gateway a fixed address on the internal network (D-203); otherwise neither. Proof: section `vectors` of `tests/vectors/workshop.json` (a run's ordered calls); `crates/officina-core/tests/workshop_vectors.rs::a_run_creates_its_networks_in_order`.
3. **The worker** (AD-102, AD-105, AD-106, FR-3 and FR-7 as amended by amendment 4, D-206). User 1000:1000; the run volume at `/work`; each mount read-only at `/work/.officina/mounts/<i>`; CPUs and memory from `[workshop]`, 1024 processes, `/tmp` a 512 MiB tmpfs; command `officina-entry run`. Environment, one exhaustive `match` over `ContainerRole` (D-206): AD-102's golden list (both cases of the proxy names, `NO_PROXY` with `::1`, `DISABLE_AUTOUPDATER`, the three `CLAUDE_CODE_DISABLE_*`, the git identity from the project's configuration, `CLAUDE_CODE_PROJECT_DIR_NAME` only when story 6.21 sets a memory name) and the credential's name alone (`--env <NAME>`, never a value), exactly one of the two names by `auth`. Only `Worker` and `Battery` carry a proxy name or a credential name. `vector::reserved_env_names()` returns the names the builders set, derived from them, for story 6.8's image check (D-233, review F13). Proof: `vector.rs::tests::{only_worker_and_battery_carry_proxy_or_credential_names, exactly_one_credential_name_per_auth, the_credential_value_never_appears_in_a_vector, reserved_names_are_derived_from_the_builders}` (iterates `ContainerRole::ALL` and `CredentialKind::ALL`); the `Worker` case of `workshop.json`.
4. **The other roles** (AD-102, D-205, D-206, D-211, D-234, D-248). `Gateway`: user 65534:65534, no volume, 0.5 CPU, 128 MiB, a `--pids-limit` derived from `gateway::MAX_TUNNELS` (twice it plus headroom for the listener and the init, review F7), command `officina-gateway` with `GatewayConfig::to_args` (story 6.5), no environment. `Packer`: the run's image id and volume, `--network none`, no credential, no mount, 1 CPU, 1 GiB, 256 processes, AD-110's git variables, command `officina-entry pack --branch officina/<name> --base <commit>`, its inputs from the vector, never from the volume's `plan.json` (review F48). `Inventory`: `--network none`, the project's mounts read-only at `/work/.officina/mounts/<i>`, a 16 MiB tmpfs at `/work/<project>` (D-211), `CLAUDE_PROJECT_DIR`, 1 CPU, 512 MiB, 256 processes (review F37), command `officina-entry inventory`. `Battery`, `BatteryGateway` (its pids limit derived as the gateway's), `Decoy` as AD-102 and AD-117 (the battery gateway's two `--add-host` test names). Proof: one case per role in `workshop.json`; `workshop_vectors.rs::every_role_has_a_case` (iterates `ContainerRole::ALL`); `vector.rs::tests::{the_gateway_pids_limit_covers_its_threads, the_packer_takes_branch_and_base_from_its_command}`.
5. **Mount sources** (AD-102, AD-107). A mount source is the project folder joined with the mount path, resolved absolute; a path holding `,`, `"` or a control character is refused (`mount_path_unsupported`, used by story 6.11, which also refuses reparse points, D-236), since `--mount` reads comma-separated fields. Proof: core `vector.rs::tests::{a_comma_in_a_mount_path_is_refused, spaces_and_accents_are_kept}`; golden cases with spaces and accented letters.
6. **Launch types and the run plan** (AD-102, AD-106, AD-107, FR-7, the gate 3 and 6 entries, D-243). `officina-core::workshop::launch` declares `ApprovedWorkshopTemplate::new(approved, current, template)` on 5.5's `ApprovedTemplate` pattern (the template present and equal in the approved and the current catalogue), `BaseChoice` (a closed-list base or an imported branch with its parent run), `LaunchFacts` (the tips, the image ids, the credential kind, the mounts' resolved sources) and `WorkshopLaunch` with private fields and one constructor, `WorkshopLaunch::new(&WorkOrder, &ApprovedWorkshopTemplate, BaseChoice, &LaunchFacts)`, taking v0.5's validated `WorkOrder` (AD-77) (review F22). `RunPlan` (schema, project, clone path `/work/<project>`, branch `officina/<work order name>`, base branch and commit, mount links, the exclude list, the `claude` argument vector, the deadline in seconds, the prompt file; Slice B's memory copy as an optional field set by story 6.21) serializes to the JSON the entry point parses with the same type. The `claude` vector is `-p --output-format stream-json --verbose --include-hook-events --permission-mode bypassPermissions --permission-prompts none --disallowedTools <WORKER_DISALLOWED_TOOLS>`, then `--max-budget-usd <amount>` (only if the gate 6 entry kept it) and `--model <alias>` when the template sets them; `WORKER_DISALLOWED_TOOLS` is the one copy, which story 6.12's `unexpected_tool` reads. `vector::run_plan(&WorkshopLaunch, ...)` and `vector::worker(&WorkshopLaunch, ...)` are the only builders of a worker's plan and vector (story 6.11 issues cards around them). Proof: the `Worker` case's plan in `workshop.json`; core `vector.rs::tests::{the_plan_round_trips, the_argument_vector_is_fixed, max_usd_and_model_follow_the_template}`; `crates/officina-core/src/workshop/launch.rs::tests::{an_unapproved_template_is_refused, a_template_changed_since_approval_is_refused}`; `compile_fail` doctests on a `WorkshopLaunch` struct literal and on `run_plan` called without one (AD-74's pattern).
7. **Worker and battery differ only where they must** (FR-15, D-210, D-235). After normalising the run id in names, the network and volume names, the mount sources, the values of `officina.role`, `officina.run` and `officina.work_order` and the command, the `Worker` and `Battery` vectors for the same image and the battery's canonical input (one mount, no memory) are equal; a worker of any other project shape differs from the battery only in extra mounts with identical options, the memory mount and `CLAUDE_CODE_PROJECT_DIR_NAME` (review F10). Proof: `workshop_vectors.rs::{worker_and_battery_differ_only_where_they_must, the_comparison_sees_one_changed_option}` (the second, its control, changes one option of the built battery vector and expects the comparison to fail); `vector.rs::tests::every_project_shape_differs_from_the_battery_only_in_mount_count_and_memory` (eight mounts and a memory folder).
8. **The plan hash** (AD-102, D-207, D-242). `plan_sha256` is the SHA-256 of the canonical JSON of the worker's and gateway's vectors and the plan, the credential's value left out, the image ids and the relative deadline in (nothing else is excluded since the gateway's deadline is relative, review F21). Proof: core `vector.rs::tests::{a_changed_deadline_changes_the_hash, a_changed_image_id_changes_the_hash}`.
9. **Documentation** (D-226). README: what a worker holds and never holds (FR-3's table, as prose); the permission mode with FR-7's reading of principle 2. Proof: review; `crates/officina/tests/readme.rs::readme_names_no_session_variable` stays green.
