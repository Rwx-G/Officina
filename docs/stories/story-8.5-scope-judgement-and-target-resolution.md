# Story 8.5: Scope judgement, target resolution and the runner's child mode

**Status:** Approved

## Story

As the author whose writes are judged on their target, for my sessions (Slice A) and for my workers' dry runs (Slice B),
I want one pure judgement of a call against my declared scope, one strict reading of the hosts an inventory lists, and one runner that can run a child, hand its output to a session or to the window, and return to its caller,
so that both slices decide scope with the same code and the same vectors, a target written as an Ansible pattern or a listing Officina cannot read fails closed instead of passing, and nothing that runs a resolution ends its own process.

## Acceptance Criteria

1. **Judgement** (AD-154 6a, FR-3 items 1 and 2, D-408, D-428). Core `relay::scope::judge(&CanonicalAction, &params, &CanonicalProject, Enforcement) -> Judgement`, first match: a read gives `read`; a write in a free project with `Enforcement::Session` gives `unenforced`; then no `target`, `out(target_undeclared)`; the target value failing `scope::is_host_name` or equal, ignoring ASCII case, to an entry of `scope::ANSIBLE_RESERVED_PATTERNS`, `out(target_not_a_name)` (review F3); the target value failing `targets` (an empty scope fails it), `out(target_not_in_scope)`; any parameter value listed in `on_order`, `out(kept_on_order)`; a declared targets action, `needs_targets`; else `in`. `Enforcement::Worker` never gives `unenforced`. `ScopeStanding` (`read`, `in`, `out`, `unenforced`) and `OutOfScopeCause` are `closed_enum!`s exported to TypeScript; from then on `ALL` and `judge`'s order are the list. Proof: section `judge` of `tests/vectors/scope.json` through `crates/officina-core/tests/scope_vectors.rs::{judge_cases_match, every_standing_and_cause_has_a_case, causes_are_checked_in_their_order, a_worker_is_never_unenforced}`; the blocking property `judge_blocking_property` (for each `OutOfScopeCause`, an exhaustive `make_fail` makes that one condition fail on an `in` case and `judge` must give it, AD-148's pattern); `crates/officina-core/tests/typescript_bindings.rs::committed_bindings_match_the_rust_types` (P-73, review F29).
2. **A target is a name** (D-428, review F3). With a permissive scope pattern (`.+`), target values carrying `:`, `,`, `&`, `!`, `*`, a leading `~` or `@`, and each entry of `ANSIBLE_RESERVED_PATTERNS` in any case, are `out(target_not_a_name)`; the reserved cases are derived by iterating the constant. Proof: `scope_vectors.rs::{host_patterns_are_not_names, every_reserved_pattern_is_out}`.
3. **The targets grammar** (AD-153, FR-3 item 3 as amended by amendment 4, D-434). Core `scope::parse_targets(stdout: &[u8], &RunFinished, max_output_kib) -> TargetsOutcome`, stdout only: the run exited 0, its stdout did not reach the targets action's `max_output_kib` (else `cut`, review F27) and is UTF-8; lines split on `\n`, a trailing `\r` removed, leading and trailing ASCII spaces removed, empty lines skipped; the first line exactly `hosts (N):` with N decimal and no other header; every other line a name under `scope::is_host_name`; N equal to the count of names and at least 1. Anything else is a `TargetsFailure` (`closed_enum!` seeded with `exit`, `timeout`, `cut`, `not_utf8`, `no_header`, `count_mismatch`, `bad_name`, `none`). The gate 1 entry's redacted listings (a group, an empty group, an unknown one, with and without `ANSIBLE_NOCOLOR`) are cases. Proof: section `targets` of `scope.json` through `scope_vectors.rs::{targets_cases_match, every_targets_failure_has_a_case, gate_one_listings_are_cases, an_escape_sequence_fails_the_name_rule, a_listing_at_max_output_is_cut}`.
4. **The names hash** (AD-153, amendment 4). `scope::names_sha256(&names)`: the SHA-256 of the names sorted and deduplicated, joined by `\n`. Indentation, order and duplicates change nothing; a name added or removed changes it. Proof: core `crates/officina-core/src/relay/scope.rs::tests::{spacing_and_order_do_not_change_the_hash, a_host_added_or_removed_changes_the_hash}`.
5. **After the resolution** (AD-153, AD-154 6b, FR-3 item 3). `scope::after_targets(&names, &CanonicalScope) -> Judgement`: every name must match `hosts`; the first that does not gives `out(host_not_in_scope)` naming it; a failed resolution gives `out(targets_failed)`; a scope without `hosts` puts no resolved name in scope. Proof: section `judge` cases with `names` through `scope_vectors.rs::after_targets_cases_match`.
6. **`launch_for` in core** (AD-29 steps 3 to 5, D-409, review F9). `relay::run::launch_for(&LaunchInputs { approved, relay, floor_path, system_dir }, project, action, &params) -> Result<relay::run::RunPlan, Refusal>` holds steps 3 to 5 with every input `plan` reads today (the approved snapshot that finds the project, the validated relay floor, the floor's path from which the project folder resolves, the system directory the launch is built with); `relay::run::plan` calls it. `officina run`'s refusals, messages and plans are unchanged. Proof: core `crates/officina-core/src/relay/run.rs::tests::{launch_for_refuses_like_plan, launch_for_builds_the_same_plan}` (the second covers a program action and an HTTP action in story 2.11's plan shape); the existing `crates/officina/tests/run.rs` cases stay green.
7. **`run_child`** (AD-31 as amended, D-409, D-1306, D-1307, review F5). Host `relay::run::run_child(&relay::run::RunPlan, RunContext, OutputSink, JobMode) -> RunResult` replaces the private `execute` of `crates/officina-host/src/relay/run/mod.rs` (host `relay::run` is a module folder as built: `args`, `consume`, `journaling`, `kept`, `output`, `request`, `send`, `spawn`): it runs one child, journals its `run_started` with `append` before spawning (a failed append refuses, as `officina run` does today) and its `run_finished` with `record` after (D-760, D-1307), from the `RunContext` (caller `Session(Option<session id>)` or `Workshop { run, relay_seq }`, `approval_id`, `tree`, `resolves`, `scope`, `targets_sha256`), and returns; it never exits the process. `JobMode::OwnProcess` is today's job holding the current process, used only by `officina run`'s final step, which then exits with the code; `JobMode::ChildOnly` assigns the child alone to a kill-on-close job right after spawn (D-64's pattern). `OutputSink::PassThrough` keeps today's streams; `OutputSink::Capture` returns stdout and stderr up to the cap. For one fake tool output of every byte value, larger than the cap, both sinks give the same bytes, SHA-256 and cut marker. Proof: host `crates/officina-host/tests/relay_run_sink.rs::{capture_and_pass_through_agree, the_cut_marker_is_the_same, a_child_only_run_returns_to_its_caller, a_held_journal_lock_refuses_before_spawn}`; the existing `crates/officina/tests/run.rs` cases (the final step still exits with the program's code; `refusal_is_journaled_when_the_lock_stays_held` and `run_end_is_journaled_when_the_lock_is_taken_meanwhile`, D-760, stay green).
8. **Run ids** (D-430, D-1306, review F12). Core `relay::approvals::run_id`, which every run host `relay::run` starts calls today, gives `{now_ms:x}-{pid:x}-{n:x}`, `n` a per-process counter; every reader of a run id (`approvals::is_valid_id`, `kept_output_name`, `satisfying_check`, the journal) accepts it and the earlier form. Proof: core `crates/officina-core/src/relay/approvals.rs::tests::{two_runs_in_one_millisecond_get_distinct_ids, an_earlier_run_id_still_reads}`.
9. **The resolution** (AD-153, D-410). Host `relay::run::resolve_targets(...)` runs the targets action with the write's values for its parameter names through `run_child` with `JobMode::ChildOnly` and the capture sink, as a run of its own (`run_started` with `resolves` naming the write's action, `run_finished`), then `parse_targets` and `names_sha256`; the caller goes on afterwards. Its stdout and stderr are kept at `relay/outputs/<run_id>.stdout` and `.stderr`, each capped at 256 KiB with D-170's cut marker, written under a temporary name then renamed, beside story 2.8's kept outputs (host `relay/run/kept.rs`) and inside the gate's `PROTECTED_DIRS` (D-1308); the hourly pass prunes every file under `relay/outputs/` older than 7 days whatever its suffix. The fake tool gains a targets mode printing a fixture listing on stdout and warnings on stderr, and counting launches (D-422). Proof: host `crates/officina-host/tests/relay_targets.rs::{a_listing_resolves_to_its_names, a_warning_on_stderr_is_kept_and_ignored, a_warning_on_stdout_fails_the_resolution, a_non_zero_exit_fails, a_timeout_fails, kept_files_are_capped_and_renamed, the_session_continues_after_the_targets_run}`; `crates/officina-host/tests/relay_home.rs::kept_outputs_of_every_suffix_are_pruned_after_7_days`; core `crates/officina-core/src/relay/journal.rs::tests::run_started_with_resolves_round_trips`.
10. **When the gate 1 entry recorded an unparsed listing** (D-403, D-428, review F39). ACs 3, 4, 5 and 9 are not built: `Judgement` has no `needs_targets`, `OutOfScopeCause` no `host_not_in_scope` or `targets_failed`; `judge` treats every write on its target value alone, D-428's name rule then carrying the whole scope. `scope.json` holds a top-level `gate1_listing_parsed` flag set from the entry. Proof: `scope_vectors.rs::sections_and_causes_match_the_gate_one_flag` (the `targets` section and the resolution causes exist if and only if the flag is true).
11. **Documentation** (D-423). `CHANGELOG.md` `[Unreleased]` under Added: target resolution. README "Relay scope and workers (v0.8, in progress)": that the scope rule matches names, never Ansible patterns (D-428), `ANSIBLE_RESERVED_PATTERNS` named; how a targets action's stdout is read (described, `TargetsFailure` named), that stderr is shown and never parsed, the names hash binding the set of hosts, the `ANSIBLE_NOCOLOR` advice per the gate 1 entry, and that an inventory mapping a name to another address, a dynamic inventory and delegation stay outside the resolution (R86). Proof: review.

- Why `run_child` (review F5): today's `execute` puts the current process in its kill-on-close job and ends with `exit_with(code)`, which terminates that job, caller included. That is right for `officina run`'s last step and fatal for a targets run inside `officina run` (the write would never start) and for the window.
- Why the run id counter (review F12): a targets run and its write inside one `officina run` can start in the same millisecond, and the window's `workshop-relay` threads share a pid; a shared id would let `satisfying_check` read a failed check as succeeded and kept outputs overwrite each other.
- `relay::scope` is pure and compiles for musl, since the container crate shares the frame types beside it (AD-150); 8.9 adds it to `ci.yml`'s musl step, replayed by the local gate (D-1303).
- The resolution is a run, journaled like any other, so its time is in the journal for section 7's Friction row (8.16).
- No employer content in `scope.json`: listings redacted to `host01`, `web01`, group `lab`, `example.org`.
