# Story 6.13: Collection, host verification, the run's outcome and `no_change`

**Status:** Approved

## Story

As the author who believes nothing written inside a container,
I want every run packaged by a separate container, copied out with a hard size bound and a fixed list of names, verified by my own git in a scratch repository that borrows my objects read-only, and its outcome decided from what host git finds, never from what the worker says,
so that a forged bundle is quarantined, no worker-chosen name is ever written to my disk, a run that changed nothing ends quietly as `no_change`, and nothing reaches my repository before I click.

## Acceptance Criteria

1. **The packer and the copy** (AD-110, D-205, D-218, D-248). When the worker has exited, however it ended, and its follower has drained: stop the gateway and drain its follower; delete any partial host `runs/<id>/out/` an interrupted collection left (review F53); create the `Packer` (the run's image id and volume, no network, no credential, no mount, its branch and base in its command) and start it attached with 120 s; then `docker cp officina-pack-<id>:/work/.officina/out -` read through the capped reader at 64 MiB plus 1 MiB; past the cap the child is killed and the run is `too_large` with nothing written. Nothing is collected while the stop flag is set. Fake engine mode: `cp` out streams a tar built from a fixture package. Proof: CLI `crates/officina/tests/workshop_collect.rs::{an_oversized_stream_writes_nothing, the_packer_has_no_network_no_credential_no_mount, nothing_is_collected_while_stopped, a_partial_out_is_deleted_before_the_copy}`.
2. **Reading the stream: names and format** (D-218, D-229; review F1, F16). Core's `workshop::tar::read` accepts regular files and directories, and PAX `x` and `g` records as metadata (honouring `path` and `size`, refusing `linkpath` and anything that changes an entry's type); it accepts only D-229's allow-list of names (`out/`, `out/tip`, `out/manifest.json`, `out/work.bundle`, and from story 6.21 `out/memory/` with segments matching D-229's segment rule), every other name, any backslash, drive prefix, colon, device name with or without an extension, trailing dot or space, or case-insensitive duplicate being `bundle_invalid`. `tip` and `manifest.json` stay in memory, each bounded (128 bytes, 64 KiB); only `work.bundle` is written to the host, as `<home>/workshop/runs/<id>/out/work.bundle`, a name Officina chooses, after the host asserts that the joined path's components are all `Normal` and that its resolved path starts with the run's `out` folder resolved the same way. Proof: section `tar` of `tests/vectors/bundle.json` (formatter-exempt): one case per hostile shape from one table (backslash, drive prefix, colon and stream, each device name form, trailing dot, trailing space, case duplicate, an extra file, a symlink, a `..` segment, an absolute name, a `linkpath` record) and gate 1's real `docker cp` stream with a long and an accented name (the gate 1 entry), through `crates/officina-core/tests/bundle_vectors.rs::{tar_cases_match, every_hostile_shape_is_bundle_invalid, a_real_docker_stream_with_pax_records_is_read}`; host `crates/officina-host/src/workshop/collect.rs::tests::{only_work_bundle_reaches_the_disk, a_path_leaving_the_out_folder_is_refused_before_any_write}`; CLI `workshop_collect.rs::an_extra_file_in_out_is_bundle_invalid_and_never_written`.
3. **Host verification** (AD-111, FR-10 as amended by amendment 8, D-219, D-220, D-231, D-238, D-239). On thread `workshop`, in `verify.git` (`git init --bare --object-format=<the project's rev-parse --show-object-format>`, its alternates naming the project's object directory, review F17), under `GitRule::Workshop`, in order, each failure a `QuarantineCause`: (1) the in-memory `tip` parsed as one object id (else `branch_missing`); without `work.bundle`, a held tip with no commit past the base goes to AC 4's table, an unheld tip is `bundle_invalid`, a held tip with commits past the base is `bundle_invalid` (D-219); with a bundle, at most 64 MiB and its reference equal to the tip; (2) `bundle::parse_header` (story 6.11): v2 or v3, v3 capabilities limited to the object format, `@filter` refused, exactly one prerequisite, the base (`wrong_base`), exactly one reference, the work branch (`extra_ref`); (3) `git bundle verify`; (4) `git fetch --no-tags --no-write-fetch-head` of the branch into the scratch repository with fsck; (5) `merge-base --is-ancestor <base> <tip>` (`wrong_base`), `rev-list --count` at most 500 (`too_large`), a count of 0 going to AC 4's table; (6) `diff --raw -z -M --no-ext-diff --no-textconv`: an added, changed or deleted path, or either side of a rename, equal to or under a mount by core's mount comparison (segment by segment, ignoring ASCII case and Unicode simple case folding, trailing dots and spaces stripped, D-231) is `mount_committed` (review F3, defensive: that checkout overwrites ignored files is the review's belief); more than `MAX_PACKAGE_FILES` paths is `too_large` (D-220); (7) `rev-list --objects`, then `cat-file --batch` fed ids only, at most 512 MiB inflated (`too_large`); (8) for display, commits (`log -z --no-show-signature`), the diff capped as AD-84, the file list whole. Core decides from the outputs: `bundle::assess(&Outputs) -> PackageAssessment` (with `commits_past_base`). Proof: section `assess` of `bundle.json` (with cases derived from each mount path: case variants, a trailing dot, the mount path itself, a deletion, a rename into a mount) through `bundle_vectors.rs::{assess_cases_match, every_quarantine_cause_has_a_case, every_mount_shape_is_mount_committed}` (iterates `QuarantineCause::ALL`); CLI `workshop_collect.rs::{each_quarantine_cause_from_a_crafted_package, a_forged_tip_never_reaches_git_as_an_option, verification_never_writes_the_project_objects, a_sha256_project_verifies_in_a_sha256_scratch_repository}` (crafted packages built by real git in fixture repositories, D-23; the second points `OFFICINA_GIT_BIN` at the logging git and asserts no argument holds the forged text, review F38; the third fingerprints the project's `objects/` before and after); core `crates/officina-core/src/workshop/bundle.rs::tests::an_alternates_path_with_spaces_and_accents_is_written_exactly` (review F44).
4. **The outcome** (AD-110, amendment 8, D-219). Core's `run::outcome(finish_cause, &PackageAssessment)` implements AD-110's table with a vector case per row: `exited` with no commit past the base on host objects is `no_change`; any other cause with no commit is `failed` with the cause; at least one commit is a package (review, or quarantine with its cause); a missing branch or an unheld tip without a bundle is a quarantined package; a failed collection is `failed` (`collect_failed`). No stream line, report or manifest text enters the decision. Proof: section `outcome` of `tests/vectors/workshop.json` through `crates/officina-core/tests/workshop_vectors.rs::every_outcome_row_has_a_case`; CLI `workshop_collect.rs::{exit_0_and_no_commit_is_no_change, a_non_zero_exit_and_no_commit_is_failed, a_report_claiming_no_changes_with_a_commit_is_a_package, a_branch_reset_to_the_base_is_no_change}`.
5. **`no_change`** (AD-110, amendment 8). The run reaches state `no_change`; one `workshop_finished` with that outcome and no `review_package`; `out/` and `verify.git` deleted at once; never a package, a quarantine or a Needs you card; not counted in `reviews_pending`; neither Import nor Discard offered. Proof: CLI `workshop_collect.rs::{no_change_writes_no_review_package, no_change_deletes_out_at_once, no_change_is_not_awaiting_a_verdict, no_change_offers_neither_import_nor_discard}`.
6. **Removal and records** (AD-110, AD-120, D-214, amendment 10). Once the package is on the host: the worker, the packer, the gateway, the volume and both networks are removed (`workshop_removed`, cause `collected`), `in/` deleted; the registry gets the package fields, the tip, `commits_past_base`, groups (story 6.15 fills them) and facts (the manifest's, bounded and untrusted); one `review_package` for a package (bundle SHA-256, counts, groups, outcome, cause); one `workshop_finished` per run, when its outcome is known (also at removal without collection and at reconciliation's `unknown`); `gateway_summary` computed by the window (allowed per host, refusals, exit code, upstream state), its host names through the run's needles (D-230). Proof: core `crates/officina-core/src/relay/journal.rs::tests::{workshop_finished_round_trips, review_package_round_trips, gateway_summary_round_trips}`; CLI `workshop_collect.rs::{the_credential_leaves_the_engine_after_collection, one_workshop_finished_per_run}`.
7. **The review view, first form** (AD-121, FR-10, D-239, D-249). `open_review(run_id)` (this story owns its `build.rs` entry, capabilities, `every_declared_command_is_allowed`, `ipc.ts` wrapper and `e2e-mock.ts` answer, review F33) asks the collector for the stored facts, computes the diff on thread `workshop` and returns as an `AuthorRequest` without deadline (review F18), caching each group's hunks per run for story 6.15's approvals; it returns `ReviewView` (ts-rs): the report tail, the run's facts (outcome, cause, duration, cost estimate, turns, hooks run and failed per event, allowed connections per host, refusals with causes, the clock skew measured at launch), commits, files, the diff, the quarantine cause; for `no_change`, the facts, the report tail, the base and the tip and `nothing_to_review: true`, with no commit, diff, group, Import or Discard. Every worker text is `Untrusted<String>`. It journals `review_opened` once, at the first Receive; this story is that kind's first writer (D-249, review F32). Stories 6.14 to 6.16 extend the view. Proof: core `crates/officina-core/src/workshop/review.rs::tests::{a_no_change_view_has_nothing_to_review, every_worker_text_is_untrusted}`; `crates/officina-core/src/relay/journal.rs::tests::review_opened_round_trips`; CLI `workshop_collect.rs::review_opened_is_journaled_once`; `crates/officina-core/tests/typescript_bindings.rs` (drift check over `ReviewView`); `app/src-tauri/src/main.rs::tests::every_declared_command_is_allowed`.
8. **Doctor** (AD-123 as amended by amendment 14). The upstream state the newest `gateway_summary` reported when `upstream_proxy` is set, "unknown" before any run. Proof: host `crates/officina-host/src/doctor.rs::tests::the_upstream_state_comes_from_the_newest_summary`.

- Why the copy is a stream (D-218): the packer runs git under the clone's own configuration, so a program it starts could still write into `out/` after the packer's own checks; summing sizes after `docker cp` into a folder would bound nothing.
- Why an allow-list of names (D-229, review F1, Critical): the names in the stream are worker-controlled, collection starts on its own once the worker exits, and on Windows `\` is a separator, `C:x` replaces the base path when joined, `tip:s` writes an alternate data stream, `CON` and `aux.txt` are devices, `TIP` overwrites `tip` and a trailing dot or space is stripped; a POSIX-only check would let a steered worker write a file of its choice as the author. Keeping `tip` and the manifest in memory leaves `work.bundle`, under Officina's own name, as the only write.
- PAX records (D-218, review F16): accepted because Docker's archive writer is believed to emit them for long or non-ASCII names (fairly sure, not verified); gate 1's saved stream is the fixture that settles it.
- Why object ids only (D-219): `tip` is worker-influenced; parsed as an object id it can never reach git as an option, a pathspec or a revision expression.
- `credential_found` (story 6.14) is checked in the same pass, after step 7; this story leaves a hook for it and story 6.14 fills it.
- A worker that resets its own branch to the base produces `no_change`: it controls its clone, so that is what the run produced (R65).
