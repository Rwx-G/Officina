# Story 6.3: The engine driver, host git resolution and the fake engine

**Status:** Approved

## Story

As the author whose workshop is driven through `docker.exe` and whose host `git` will read worker-made objects,
I want both programs resolved from places no session can write, every engine call built in core as a typed vector, run by one host function with a stripped environment, and the calls that create anything compiled only into the window,
so that no CLI path a session can reach starts a container, no child of Officina carries a credential it does not need, nothing the engine returns hands the credential back, and the tests can drive the whole workshop against a fake engine.

## Acceptance Criteria

1. **Resolution** (AD-98, AD-111, AD-51, D-224). `officina-host::workshop::engine::resolve` takes `OFFICINA_DOCKER_BIN`, else `BinPath` from `HKLM\SOFTWARE\Docker Inc.\Docker\1.0` joined with `docker.exe`, else `docker.exe` on `PATH`; `host::git::resolve` takes `OFFICINA_GIT_BIN`, else `InstallPath` from `HKLM\SOFTWARE\GitForWindows` joined with `cmd\git.exe`, else `git.exe` on `PATH`. On Windows only a file ending in `.exe` is accepted (a shim is refused, AD-51); the key's version values are never read. Off Windows (CI only, D-224) the override or `PATH`, with no extension rule. The result carries its source (`override`, `hklm`, `path`). `platform::windows` gains the HKLM string read (`Win32_System_Registry`). Every `host::git` call uses the resolved binary, the tree fingerprint (2.6) and the meeting (5.10) included, which closes story 2.6's note. Proof: host unit `crates/officina-host/src/workshop/engine.rs::tests::{the_override_wins, a_cmd_shim_is_refused, the_source_is_reported}` and `crates/officina-host/src/git.rs::tests::{resolution_order_is_override_hklm_path, a_non_exe_git_is_refused}` (the registry read injected as an argument); `crates/officina-host/src/platform/windows.rs::tests::reads_a_known_hklm_string` (Windows only, reads `ProductName` under `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion`); the existing `relay_tree.rs` and meeting tests stay green unchanged.
2. **Engine calls in core** (AD-98, D-204, D-205, D-206, D-243). `officina-core::workshop::engine` declares the `closed_enum!` `EngineCallKind` (AD-98's calls plus `info`, `network ls`, `volume ls`), `EngineCallKind::is_launch()` as one exhaustive `match`, and `EngineCall` with private fields built only by per-kind builders from typed inputs (`compile_fail` doctest on a struct literal). `officina-core::workshop::vector` declares the `closed_enum!` `ContainerRole` (`Worker`, `Gateway`, `Packer`, `Inventory`, `Battery`, `BatteryGateway`, `Decoy`) and `ContainerVector` with private fields and no builder (story 6.6 adds the builders and alone owns the fixed options and labels); `EngineCall::create(&ContainerVector)` copies its arguments, and this story's golden `create` case uses a `#[cfg(test)]` vector that story 6.6 replaces. Deadlines follow AD-98 and D-205 (attached starts take their role's). `inspect` runs with `--format` selecting `{{json .State}}` and `{{json .Config.Labels}}` only, never the full object, whose `Config.Env` holds the credential's value (D-206, review F14). Parsers: `EngineInfo` from `docker version --format "{{json .}}"` (`not_running` without `Server`, `windows_containers` when `Server.Os` is not `linux`); `info`'s memory, CPUs, `SystemTime` (D-242's skew) and a digest of its security options, runtimes and proxy fields; `EngineKey` from `Platform.Name`, `Server.Version`, `KernelVersion` and that digest (D-232, review F52); `ps`, the formatted `inspect` (state, exit code, `OOMKilled`, labels), `image inspect` (id, labels, env names), `network ls` and `volume ls` rows. Golden: section `engine` of `tests/vectors/workshop.json` (formatter-exempt), one case per kind and per parser input, including fixture outputs from the workstation's engine (versions only, no host names). Proof: core `crates/officina-core/tests/workshop_vectors.rs::{every_engine_call_kind_has_a_case, engine_cases_match_their_builders, engine_outputs_parse_as_recorded, inspect_never_selects_the_environment}` (the first iterates `EngineCallKind::ALL`); `crates/officina-core/src/workshop/engine.rs::tests::{is_launch_names_every_kind, windows_containers_are_unavailable, a_missing_server_is_not_running, a_changed_security_option_changes_the_engine_key}`.
3. **Names and labels** (AD-98). `officina-core::workshop::names`: the floor key (AD-8's FNV-1a of the normalised floor path, 16 hex, `quota::fnv1a`), a run's object names from its id (`officina-worker-`, `-gateway-`, `-pack-`, `-int-`, `-out-`, `-vol-`), image tags `:local`, the label set (`officina.managed=1`, `officina.floor`, `officina.version`; for a run `officina.run`, `officina.role`, `officina.work_order`). Proof: core `crates/officina-core/src/workshop/names.rs::tests::{object_names_derive_from_the_run_id, every_role_has_its_label, the_floor_key_is_the_quota_fnv}` (the second iterates `ContainerRole::ALL`).
4. **Execution and environment** (AD-98, D-206, D-64, D-224). `engine::execute(&ResolvedDocker, &EngineCall, &EngineEnv) -> Result<EngineOutcome, EngineError>` is the one function that turns a vector into a process: `CREATE_NO_WINDOW`, working directory the Officina home, stdin null except attached starts, stdout capped at 1 MiB except followers and D-218's stream, the first 2 KiB of stderr kept, deadlines per kind. On Windows the child is in a kill-on-close job assigned as soon as it exists; off Windows (the CI `workshop` job) there is no Job Object and the deadline kills the direct child (review F56). The process environment is one exhaustive `match` (D-206): the base environment minus `SESSION_ENV_REMOVED`, every `OFFICINA_*` name, `CLAUDE_CODE_OAUTH_TOKEN` and `ANTHROPIC_API_KEY`, compared ignoring ASCII case on Windows; `NoDefaultCurrentDirectoryInExePath=1`; the credential added only where a later story's role rule says (here: never). Proof: host unit `engine.rs::tests::{the_environment_rule_names_every_kind, removals_ignore_case, closing_the_job_ends_the_child}` (the last makes AD-98's "a closed window leaves no `docker.exe` behind" executable: dropping the job ends a fake engine child holding a sleep); CLI `crates/officina/tests/engine.rs::{seeded_session_and_credential_names_never_reach_docker, a_deadline_kills_the_child, stdout_is_capped}` (the base environment holds every name of `SESSION_ENV_REMOVED`, iterated from the constant, `OFFICINA_HOME`, `Claude_Code_OAuth_Token` in mixed case and `ANTHROPIC_API_KEY`; the fake engine's log shows none of them for any kind).
5. **Authority split** (AD-97, AD-21 as amended, D-204, D-9). The launch half (every kind whose `is_launch()` is true) compiles under `window-authority`, its error type carrying `AUTHORITY_MARKER`; built without the feature, `execute` refuses those kinds before any process starts with an error carrying no marker. `officina.exe` keeps the read half for `stop --all`, `workshop --json` and doctor. Proof: host unit `engine.rs::tests::execute_refuses_every_launch_kind_without_the_feature` (compiled only under `#[cfg(not(feature = "window-authority"))]`, iterates `EngineCallKind::ALL` through a resolver pointing at a path that does not exist and asserts the refusal variant, since a spawn attempt would return a different error and `--lib` builds no fake engine, review F35); a CI step on `core-linux` and `windows` running `cargo test -p officina-host --lib workshop::engine` alone; the CI step "officina holds no authority" stays green.
6. **The lint** (AD-97, D-204, D-128). `workshop::engine` is the fourth `expect(clippy::disallowed_methods)` site. Proof: `crates/officina-host/tests/spawn_lint.rs::command_new_is_expected_in_four_modules_only` (renamed from three; compares the files holding the attribute with `spawn`, `relay::run`, `git`, `workshop::engine`).
7. **The workshop git rule** (AD-111, D-22, D-128, D-238). `host::git` gains `GitRule::Workshop`: D-22's flags, `GIT_OPTIONAL_LOCKS=0`, the caller's `GIT_*` names removed, `-c core.hooksPath=<home>/workshop/empty-hooks` (created by the window, refused unless empty), `-c transfer.fsckObjects=true -c fetch.fsckObjects=true`, `-c protocol.allow=never -c protocol.file.allow=always`, `-c gc.auto=0 -c maintenance.auto=false -c fetch.writeCommitGraph=false -c fetch.recurseSubmodules=false -c submodule.recurse=false`, `-c log.showSignature=false` and `--no-show-signature` on every `log` (review F17), `CREATE_NO_WINDOW`, 60 s per call, each call in a kill-on-close job assigned as soon as the child exists, since `cmd\git.exe` is a launcher that starts the real git (defensive: the review's belief, not verified here); reading `user.name` and `user.email` is the one call that keeps the global configuration's meaning. Proof: host unit `git.rs::tests::{the_workshop_rule_carries_every_flag, a_non_empty_hooks_dir_is_refused}`; host integration `crates/officina-host/tests/git.rs::{a_planted_hook_never_runs_under_the_workshop_rule, without_the_rule_the_planted_hook_runs, a_global_gpg_program_never_runs_on_log, a_grandchild_is_gone_after_the_deadline}` (a `reference-transaction` hook in a fixture repository writes a marker; the second is its control; the third puts `log.showSignature=true` and a marker `gpg.program` in the test home's global configuration and logs a signed fixture commit; the fourth points `OFFICINA_GIT_BIN` at a fake git that starts a sleeping grandchild; each skips with a reason when no git exists, D-23).
8. **The fake engine and the logging git** (D-223). `crates/officina/src/bin/officina-fake-docker.rs` (`test = false`), configured by `FAKE_DOCKER_*` or a `fake-docker.json` sidecar (D-86), keeps its state in a JSON file beside the sidecar and appends one log line per call, `{"argv": [...], "env_names": [...]}`, names sorted, never a value. Modes here: `version` (`linux`, `windows`, `down`), `info`, `ps`, `inspect` (its state holding a seeded value in `Config.Env` that the formatted call never returns), `image inspect`, `network ls`, `volume ls` from state; later stories add theirs. `crates/officina/src/bin/officina-git-logger.rs` (`test = false`) logs its argument vector as one JSON line and runs the real git with it (review F38). Proof: CLI `crates/officina/tests/fake_docker.rs::{the_log_is_one_json_object_per_call, version_modes_answer_as_recorded, state_survives_between_calls, formatted_inspect_never_returns_the_seeded_env}`; `crates/officina/tests/git_logger.rs::the_logger_passes_through_and_logs_argv`.
9. **Engine state in the window** (AD-98, AD-3 as amended, D-239). Threads `workshop` (short engine and git jobs, one at a time) and `workshop-build` exist; the collector never runs `docker` or the workshop's git. At window start the `workshop` thread reads `EngineInfo` with a 10 s deadline and sends it to the collector as an `AuthorRequest` without deadline (D-135's outcome pattern). Proof: CLI-crate collector test `crates/officina/tests/watch.rs::{the_engine_state_reaches_the_collector, the_collector_never_spawns_docker}` (the second asserts the fake engine's and the logging git's logs stay empty while only the collector runs; stories 6.11 and 6.15 extend it).
10. **Doctor** (AD-123, D-228). Doctor reports `docker.exe` and `git` with their source, failing on a shim; `DOCKER_HOST`, `DOCKER_CONTEXT`, `DOCKER_CONFIG`, `OFFICINA_DOCKER_BIN`, `OFFICINA_GIT_BIN` and `OFFICINA_LINUX_BIN_DIR` named when set; in the Docker CLI's `config.json` (read, never written) a `proxies` entry, `currentContext` and `cliPluginsExtraDirs` named; `DOCKER_HOST=tcp://` without TLS warned (review F40); the engine reachable, Linux, its `EngineKey`; orphan `officina.managed` networks and volumes counted. Each check is a variant of the doctor's workshop check enum with its level (D-228; story 6.24 orders the section). Proof: host `crates/officina-host/src/doctor.rs::tests::{docker_and_git_sources_are_reported, a_docker_shim_fails, overrides_are_named, docker_cli_config_entries_are_named, a_plain_tcp_docker_host_warns, windows_containers_fail}` (environment, registry reader and config file as arguments).
11. **Documentation** (D-226). `CHANGELOG.md` `[Unreleased]`: under Added, the engine driver; under Security, `git` and `docker.exe` resolved from install locations before `PATH`, the workshop git rule, and `inspect` never reading container environments. Proof: review.
